拼接补回了什么

两次模型上下文读取经过不同处理 Task，最终都拼回首个请求创建的同一个队列 Task。后续入队则拼回它自己的请求 Task，因此可以定位处理任务继承了哪条创建链。

先看协程执行栈，再沿拼接点追溯创建栈和更早的调用者。各栈块保留原有帧顺序。

案例结论

本地复现结果
存档中的 Ray Serve 原始应用在 2.48.0 上用首个批请求的模型 ID 回答后续批请求。不启用探针时，两种发起顺序各有六个批请求中的三个选错模型，两条普通请求都正确。Ray 2.54.0 在两种顺序下的十二个批请求均返回正确的模型 ID 和输入项。
CoroPerf 证据说明
两个模型 ID 读取的执行栈相同，读到的都是首个模型 ID。按两个不同处理 Task 的创建记录分别拼回 68 → 63 → 55 → 53 和 106 → 101 → 55 → 53。两条链都经过首个请求创建的队列 Task 55。后续入队记录 80 则属于单独创建的 Task 78。修复版对照记录了每个入队项自身的模型 ID，并在调用批处理方法前按模型 ID 分组。
适用范围与局限
实验使用报告者的部署，模型值是本地字符串。调用栈覆盖一个模型副本，通过串行 HTTP 请求日志独立核对客户端请求和返回值。源码对照核查了 PR #59334 加入的模型 ID 分组。实验覆盖模型选择和返回顺序。
