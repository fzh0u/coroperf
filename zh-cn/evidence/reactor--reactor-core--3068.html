案例结论

本地复现结果
Reactor 3.8.8 的一次有界检查确认：强制关闭 bounded-elastic 调度器会中断正在运行的 SchedulerTask。原生 InterruptedException 栈能定位阻塞操作，但没有之前已返回的 submitOrderSynchronization 提交入口。
CoroPerf 证据说明
标准 JDI 记录真实 SchedulerTask 的构造接收对象和中断工作线程栈中的接收对象，两者的对象 ID 都是 431。另行读取应用 returnedTask 字段，确认它也是同一对象。CoroPerf 将保存的创建和中断事件接起来，恢复历史提交入口。
适用范围与局限
这是单任务组件改编：用 Thread.sleep 代替报告中的阻塞 HTTP 等待。中断符合 dispose 的强制关闭语义，本案例验证创建入口归因，不声称 API 契约错误。工作负载只执行一次。采集器保存证据后在子进程退出收尾中以 1 退出，原生进程退出码未验证。采集止于中断，没有终止事件不代表任务仍存活或泄漏。未运行优雅关闭变体、修复、多版本、生产流量或开销测试。
