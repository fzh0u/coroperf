案例结论

本地复现结果
第一个分词后端草案在所测 SGLang 路径上同步等待 worker 结果。加入异步等待的草案后，结果由 await 接收。两个版本使用同样的双 worker CPU 池，两个测试会话都回到各自绑定的 worker。输出 token ID 与参考分词器全量编码一致。七次未开启采样的预热对照中，两条请求启动后立即入队的回调延迟中位数从 1.37 毫秒降至 0.139 毫秒。
CoroPerf 证据说明
两条结果都经过同一个收集线程，Scheduler._finish 的执行栈完全相同。按实际回调对象，原草案的两个结果分别拼回 3 → 2 → 0 和 5 → 4 → 1。使用 await 的草案分别拼回 10 → 8 → 6 和 11 → 9 → 7。回调闭包持有实际 Future，_set_result 也将原结果对象交给该 Future，因而能核实每个结果回到哪个请求。
适用范围与局限
实验使用固定版本的 SGLang 分词方法、TokTier 0.3.0、两个实际本地 worker 进程和两个合成 Qwen3 会话。测量范围是事件循环回调延迟和 token 一致性。完整服务启动、GPU 首 token 延迟和其他分词配置仍待验证。RFC 仍开放，worker 草案 PR #44382 在合并前关闭。
