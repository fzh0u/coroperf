拼接补回了什么

案例结论

本地复现结果
存档中，原版 SDK 的两条本地向量查询都人为延迟应答 200 毫秒。两个同步读取在同一事件循环上串行。第二个路由任务读取结束后，第一个已经创建的下游查询才开始。未开启探针的同一组对照中，两个查询合计从约 416 毫秒降到提案版的 260 毫秒，返回节点一致。
CoroPerf 证据说明
两条相同的同步读取栈分别拼回 31 → 28 和 38 → 29。两个下游查询分别拼回 44 → 36 → 28 和 46 → 43 → 29。另一个路由 Task 开始读取时，第一个下游 Task 36 已经创建。按同期记录核对，第二条同步读取占了第一个下游 Task 从创建到执行间隔中的约 202 毫秒。
适用范围与局限
存档实验使用报告版本和带受控应答延迟的本地中继。新跑的纯 CPU 回归测试在当前路由源码上核对同一行修复。检索器实现异步 I/O 时，回调能在两个检索结束前运行；仍继承同步 fallback 的检索器依然会阻塞。两版工具查询返回值一致。Issue 和修复 PR 均仍开放。
