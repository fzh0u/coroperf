Reactor #4478：清理工作线程来源

一次未使用 scheduler 的清理很快返回，但内部非守护工作线程仍存活，JVM 等待其空闲超时后退出。

上游报告 · 保存的证据与哈希

库 / JDKReactor 3.8.8 · reactive-streams 1.0.4 · JDK 21.0.1
清理返回109.00 ms
清理后的工作线程仍存活 · 非守护 · TIMED_WAITING
JVM 自然退出10.17 s
准备与首轮检查84.45 s · 执行一次

接合补充了什么

工作线程的物理栈仅有空闲队列及执行器；创建栈指出 SchedulerState 清理机制和已经返回的 beginDisposeApplication。CoroPerf 共享分析通过同一个保留的 Thread 对象及其 Java Thread ID 接合两条记录。

明确新增的 ThreadFactory 观察器调用原工厂，原样返回其 Thread。它记录资源创建，不提供协程父图或自动语义诊断。
