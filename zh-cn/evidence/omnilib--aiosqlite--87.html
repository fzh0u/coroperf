案例结论

本地复现结果
提交并重新打开数据库，主键 1 的名称确已更新；原评论的 >0 分支在返回 2 时会把另一项目当作目标。
CoroPerf 证据说明
CPython 在 execute 时将本连接 sqlite3_last_insert_rowid() 存入该游标。project=101 的冲突更新保留同连接上次成功插入的 ID 2，按大于零直接返回就会指错行。常规插入 project=303 得到的 2 则正确。反向交错时，连接寄存值已变 3，较早执行更新的游标仍为 0。唯一键查询与磁盘行确定了返回值所指的项目。
适用范围与局限
完整复现范围为公开评论的参数化 SQL 与回退代码。键值、种子行及两任务顺序由本地测试设置。报告人的 Windows 10 项目及 SQLite 实例未提供；本地 SQLite 版本取自 CPython 3.8.5 的 Windows 构建清单。栈佐证正确游标上的读取，判定错误目标需要 SQL 历史和持久化行。 协程来源来自本地并发调用，原评论的标准库代码为同步调用。
