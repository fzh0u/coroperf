拼接补回了什么

核对实际等待的 Event 和 Task，将两个相同的回复执行栈接回交互和批量请求的创建栈。再用实际请求 ID 跨两条 detokenizer 路由，将同一个调度器消息的传输耗时归到两个调用者。

先看协程执行栈，再沿拼接点追溯创建栈和更早的调用者。各栈块保留原有帧顺序。

案例结论

本地复现结果
将夹具中的 25 毫秒延迟从路由器读取前移到路由器首次转发时，两段耗时随之变化。每种对照各五次，PR #45036 记录的处理时间中位数分别为 0.97 和 25.94 毫秒，观测到的发送至接收时间分别为 25.49 和 0.29 毫秒。本地补丁在 Pickle IPC 上测得的这段时间分别为 25.77 和 0.33 毫秒，在 MsgPack IPC 上分别为 25.69 和 0.24 毫秒。两条请求的 token ID 都一致。
CoroPerf 证据说明
交互和批量请求在相同的执行栈恢复。按实际的请求 ID 找到前端唤醒的 Event，再核对等待它的 Task 和协程对象，把观测 4 接回创建记录 1，把观测 6 接回创建记录 2。这两条回复原本同属一个调度器消息，随后经过不同的 detokenizer 路由。拼接把这个消息上测到的分段等待归到两个应用调用者。
适用范围与局限
CPU 夹具运行 SGLang 的发送端、路由器、Unix IPC 和前端输出分发。调度器消息和解码输出由夹具提供。本地补丁采集同机的发送至接收时间，包含序列化和反序列化。GPU 吞吐和线上报告的排队耗时仍待验证。Issue 及处理时间指标 PR 均开放。
