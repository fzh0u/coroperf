案例结论

本地复现结果
一次维护者提供的 raw-asyncpg 示例运行中，十个 Task 共用一个真实 PostgreSQL 连接：九次 prepare 报原生 InterfaceError（另一个操作正在进行），一次返回数据。gather(return_exceptions=True) 用于有界清理；连接关闭、PostgreSQL 日志确认关闭，进程退出 0。
CoroPerf 证据说明
CoroPerf 将九个异常栈逐一接回实际 Task 创建记录，恢复原生异常栈缺少的日志与审核提交辅助函数。明确增加的 API 观察记录了十个真实 Task 使用同一 Connection/protocol 对象，从而把提交来源与共享资源联系起来；Task 创建祖先关系本身不能证明连接归属。
适用范围与局限
范围是 asyncpg0.29.0 的维护者独立驱动组件，不是原始 Discord bot 或 SQLAlchemy1.4 beta ORM。两个具名提交辅助函数与有界异常收集是归因适配，函数名不是恢复出的 Discord 注册入口。保留两次早先认证失败；只有一次成功执行的并发 prepare/fetch 工作负载。没有每 Task 独立连接的修复、多版本或查询重跑，上游修复建议未经本地验证。
