案例结论

本地复现结果
MySQL 拒绝第二次插入相同主键时，父提交的 QueryFailedError 栈从 Query.onResult 开始，缺失调用 repository.insert 的 myNamedFunction1234。
CoroPerf 证据说明
上游 #11273 指向 #11271，合并的 #12056 续接该提案。真实 Mocha 回归的旧栈定位到 MySQL 回调内包装错误；async_hooks 创建栈和 V8 对象等值核对将该异常追到 myNamedFunction1234 返回的同一 Promise。合并后在 query 的 catch 内抛错，原生栈恢复 InsertQueryBuilder.execute 与第二次 insert 的调用行。
适用范围与局限
本次使用合并 PR 的公开重复主键回归；原帖描述的是查询错误和丢失调用栈。两版本均返回 1062/23000，首行保持 Incubus，独立对照和服务重启均确认持久化结果相同。同一对象证据限于交给 Chai 的测试函数 Promise，回调在另一 Promise 中执行。
