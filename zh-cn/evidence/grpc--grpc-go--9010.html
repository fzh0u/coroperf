案例结论

本地复现结果
Go1.23.0/grpc1.60.1 的一次真实 bufconn Health/Check RPC 返回 SERVING；受控子 goroutine171 在 30 毫秒有界快照中等待 channel。原生子栈仅记直接创建函数 enqueueContinuation，更早的服务端 handler goroutine170 已不在快照中。正常清理子任务与服务端，进程退出 0。
CoroPerf 证据说明
标准 runtime trace 记录 goroutine171 诞生时经过 service.Check、生成的 gRPC handler 和 Server.processUnaryRPC 的完整创建栈。子任务自报原生 ID、独立全 goroutine 快照与 trace ID 一致。CoroPerf 将创建记录接到等待栈，恢复当前栈缺少的历史 gRPC 方法入口；trace 等待区间约 30.96 毫秒。来源信息本来就在 Go trace 中，工具提供统一身份关联与合并视图。
适用范围与局限
这是在缓存 Go1.23/grpc1.60.1 上展示 #9010 诊断问题的受控组件，不是当前 Go1.27 回归、原始 goroutine label 实现或 panic/crash 复现。只运行一个进程内 RPC 和一个子 continuation；不证明服务卡住、资源泄漏、跨进程请求 ID 或完整 RPC 因果图。没有新版 label、修复版或额外 RPC 对照。
