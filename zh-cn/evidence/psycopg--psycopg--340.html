案例结论

本地复现结果
有界的共享连接对照确认：通知迭代持有驱动连接锁时，查询会等待。另设历史调用者扩展：每个生成器产出同一条通知后被移交，原读取 Task 随后被回收。后续两条查询拥有相同的原生 await 栈，PostgreSQL 后端均为空闲。生成器帧与分配栈、当前 Task 的创建栈及协程起源，都缺少已经结束的读取入口。
CoroPerf 证据说明
在成功取锁时记录实际运行的 Task；返回生成器的真实挂起帧指向同一个连接锁。后续查询等待该锁时，中间没有释放事件。沿锁的获取历史接回 Task 创建，即使取锁 Task 已被回收，仍可恢复 start_report 或 start_refresh。两个独立批次覆盖两个驱动版本及两种读取、查询顺序，共验证 32 个历史调用者。资源等待关系与创建关系分别保存。
适用范围与局限
实验使用纯 Python 实现的 Psycopg 3.2.3、3.3.9，CPython 3.12.16，以及本地私有数据库上的 PostgreSQL/libpq 14.13。四个有界对照检查报告中的共享连接与独立连接机制，未执行 2022 年的原始程序；历史读取入口扩展另行标明。显式关闭已暂停的生成器后，锁释放且查询返回 42；32 个提前关闭生成器的对照都无需等待。这是应用清理措施，不声称修复了驱动。删除锁历史或 Task 创建记录后均无法归属。展示的拼接连接历史取锁采样，不把已结束的 Task 说成实时持锁者，也不把取锁者说成查询 Task 的创建者。
