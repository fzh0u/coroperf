案例结论

本地复现结果
Go 1.23.0 的一次检查使用原报告的两个 io.Pipe 和 io.Copy。关闭目标写端后，复制在 80 毫秒观察窗口内未返回；goroutine 161 仍阻塞于 pipe read。原生 dump 只有直接创建者 startCopy，没有 submitConsoleMirror。正常清理时关闭自有源端，使这同一次运行结束，进程退出 0。
CoroPerf 证据说明
标准 runtime trace 记录真实 goroutine 的诞生及完整创建栈、pipe read 等待转换和最终退出。子 goroutine 自报的原生 ID 与独立全 goroutine 快照都匹配 trace 中的 161。CoroPerf 将创建记录接到阻塞栈，恢复 submitConsoleMirror；原生等待区间约 80.82 毫秒。创建来源原本就存在于 runtime trace，CoroPerf 提供统一身份关联及合并视图。
适用范围与局限
这是加入具名提交辅助函数的原始进程内管道示例，只有一次有界观察；不证明无限存活、socket 或描述符泄漏、Docker 集成问题或 runtime 缺陷。只执行一次传输。关闭源端属于结束同一次运行的清理，没有替代实现、重复传输、多版本或修复验证。
