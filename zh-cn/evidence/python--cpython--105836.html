案例结论

本地复现结果
两个外层 Future 都已显示取消，而内层 Task 还在清理。在第一次事件循环检查点，3.10.12 中两个 Task 都尚未进入清理，3.14.3 中两个都已进入。回调仍在队列时，原生调试信息包含提交者。回调处理后，Task 创建栈和 coroutine origin 都缺少提交者，3.14.3 的调用图也只显示相同的清理路径。
CoroPerf 证据说明
CoroPerf 记录 _chain_future 实际收到的两个对象。Task 快照接回同一 Task 的创建栈，再通过外层 Future 跨线程接回 launch_profile 或 launch_inventory。两个版本、两种发起顺序共 16 次观测，均通过 Future 和 Task 对象身份的独立核对。
适用范围与局限
页面展示 CPython 3.10.12 上的 Linux 双调用者实验。相同测试也在 3.14.3 上核对了取消时间点与原生诊断。实验暂时挂起清理以便观测，之后释放并确认两个 Task 均完成取消。
