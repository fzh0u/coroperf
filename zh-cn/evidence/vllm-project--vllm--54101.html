案例结论

本地复现结果
八个请求以每秒 50 个的速率发起，并发上限为 1，本地回环服务固定等待 100 毫秒。原版平均端到端延迟为 101.9 毫秒。合并修复后，原口径仍为 101.9 毫秒，另报告平均客户端排队 287.4 毫秒、含排队的平均端到端延迟 389.3 毫秒。两版返回内容一致。
CoroPerf 证据说明
八个 Task 中有七个遇到已占用的 semaphore。请求 2 和 7 的等待栈和发送栈各自相同。用实际 Task 和 RequestFuncInput，将等待记录 5、发送记录 17 拼回创建记录 4，将等待记录 16、发送记录 22 拼回创建记录 15。该次采集中，从进入 semaphore 到 HTTP 客户端开始计时，两个请求分别经过 166 和 581 毫秒。
适用范围与局限
对照运行两个固定版本的基准函数及真实 HTTP 客户端，服务端使用确定性的回环响应。合并版从提交基准 Task 计客户端排队，有限速率运行另报告含排队的端到端延迟。池化路径也通过了同一计时核对。实验范围限于基准客户端和回环服务。
