案例结论

本地复现结果
两个生产者 Task 抛出不同的 ValueError 对象，消息和抛出栈相同。在 Nuitka 4.2.2 中，将保存的异常注入尚未启动的编译型异步生成器后，回溯丢失 make_exception。Nuitka 4.3 和解释运行的 CPython 保留该帧。各版本中，两次接收的异常回溯、Task 创建栈和协程起源分别相同，都缺少原始发起者。
CoroPerf 证据说明
CoroPerf 在交接前记录首次抛出位置 make_exception（记录 3 和 4），分别接回 launch_profile（1）和 launch_inventory（2）创建的生产者 Task。接收 Task 创建时（7 和 8）收到的异常对象，与注入后捕获的对象（9 和 10）相同。页面标出的 1 → 7 → 9 和 2 → 8 → 10 分别恢复两个原始发起者。首次抛出的观测还展示了旧版接收回溯中丢失的帧。
适用范围与局限
Linux x86-64 上用两个生产者 Task 和两个接收 Task 扩展原帖的 athrow 示例。对照包括在 CPython 3.11.15 上编译的 Nuitka 4.2.2 和 4.3，以及解释运行的 CPython。两批实验共核对 48 条接收拼接，独立改变发起顺序和交接顺序。去掉异常对象的交接边后，接收回溯只能接回共享的调度入口。采集使用定点 Python 探针和 CoroPerf asyncio agent。
