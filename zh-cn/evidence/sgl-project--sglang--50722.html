拼接补回了什么

两条相同的接收栈分别接回各自的输出 Task 和 ASGI 请求创建栈。监听样本也能接回其中同一个请求，表明逐块检查是输出 Task 上的额外工作。

先看协程执行栈，再沿拼接点追溯创建栈和更早的调用者。各栈块保留原有帧顺序。

案例结论

本地复现结果
独立 HTTP 流式实验中，变更前、受影响提交、合并修复后的无采集吞吐中位数分别是 49,336、23,507 和 47,340 块/秒。两次短流采集中，256 个受影响的输出任务各对 8 个分块执行了 7 次检查。修复后每个输出任务各检查 1 次。
CoroPerf 证据说明
cProfile 能给出检查总次数及直接调用者。按实际 Task 将相同的取消接收栈记录 1977、1978 分别拼回输出 Task 创建记录 1463、1208，再回到不同的 ASGI 请求创建记录 951、696。记录 2881 则显示，创建输出 Task 1463 的那个请求 Task 同时运行着独立的断连监听。
适用范围与局限
实验使用固定版本的 SGLang 流式方法、真实回环 TCP、Starlette 和 Uvicorn，输出分块由受控数据源提供。中位数取自每个版本四次无采集运行。原报告的 GPU 模型吞吐没有在本次实验中测量。PR #50741 已合并。
