案例结论

本地复现结果
草案 CoreCLR 的异步栈模式在直接 await 时显示 Program.DirectOuter。经过同步 Task 转发后，两条恢复栈的业务方法都只有 Program.Callee。TPL 事件携带 Task ID，但操作名相同。标准 dotnet-trace 的 Speedscope 视图和启用任务追踪的 TraceEvent 工作线程栈也都缺少两个发起者。
CoroPerf 证据说明
CoroPerf 在 TraceOperationBegin 记录物理创建栈。用采样线程上活跃的 TPL Execution 区间确定该采样所属的 Task，再按同一个 Task ID 找到创建记录。页面里，Task 4 的执行区间为记录 4–8，将观测 5 连回记录 2 中的 LaunchInventory。Task 1 的区间为记录 9–13，将观测 10 连回记录 0 中的 LaunchProfile。两种发起顺序共 8 次观测，均通过独立记录的 Task ID 和 await 后检查点核对。
适用范围与局限
这是按上游同步转发示例扩展的双调用者实验，运行于 Linux x64 和 CoreCLR 草案提交 7e2cfb7b13b5。采集依赖这版运行时的 TPL 创建和执行事件。采样分析对照使用 dotnet-trace 10.0.750501 和 TraceEvent 3.1.23，并在 await 后留出短暂采样窗口。
