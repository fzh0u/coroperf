案例结论

本地复现结果
原帖的十行程序在 Ray Data 2.43.0 开启 preserve_order 时返回空列表。两个分块的管理协程各把一个尚未完成的 asyncio Task 当成函数调用，触发 TypeError。清理逻辑先写入结束标记，消费者读到它时，五个批任务还没写入数据。
CoroPerf 证据说明
执行记录 22 和 58 显示 process_batch 写入数据。它们分别接回 process_all_batches 在记录 1 和 37 创建的实际 Task。这两个对象也是记录 7 和 43 中导致异常的调用操作数。沿关系还可以接回两个管理协程的创建记录 0 和 31。实际队列与 Task 世代区分了两个分块。
适用范围与局限
在本地 CPU Ray 集群运行原帖十行程序。原帖的开发版未给出提交号。本地对比 2.43.0、2.45.0，以及只将 await task() 改为 await task 的 2.43.0 对照。新版本和单行改动均按原顺序返回全部十行。
