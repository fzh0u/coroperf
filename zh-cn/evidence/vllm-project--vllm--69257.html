拼接补回了什么

先看协程执行栈，再沿拼接点追溯创建栈和更早的调用者。各栈块保留原有帧顺序。

案例结论

本地复现结果
报告版本和所核对的主分支均发送两次探针，两次都收到 HTTP 503。每次运行的主负载均成功一次、失败一次。终端和 JSON 都漏掉两个探针计数。开放的 PR #69262 以及应用同一补丁的主分支均报告探针成功 0 次、失败 2 次。探针全部失败时仍不输出延迟统计。部分探针失败、全部成功和关闭探针的对照仍按预期报告。
CoroPerf 证据说明
三次失败响应都进入完全相同的 aiohttp 接收栈，回调时没有正在运行的 Task。通过同一个实际 ResponseHandler 接回各次发送，再用实际 asyncio Task 把记录 1、2 接回同一个探针创建记录 0，把记录 4 接回主负载的创建记录 3。函数返回的 RequestFuncOutput 就是基准程序两个结果列表中的对象，由此确认漏计的是这两次探针失败。
适用范围与局限
实验运行原始的基准参数解析、任务调度、HTTP 客户端、终端摘要和 JSON 写入，响应由本机回环服务固定提供。结论覆盖基准客户端的报告和任务归属。模型生成与真实推理吞吐量未测量。Issue 和 PR 均仍开放。
