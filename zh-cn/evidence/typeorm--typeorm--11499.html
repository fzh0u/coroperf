案例结论

本地复现结果
真实 SQL Server 的 YYY int NOT NULL 列收到参数 NULL，报 515、EREQUEST。报告版本 0.3.24 的原生栈从 SqlServerQueryRunner.js:204 开始，缺少应用调用行。合法写入可由独立连接读回。
CoroPerf 证据说明
用运行时记录的 Promise 身份区分两个应用调用。应用返回的实际 async Promise 的创建帧是 importOrders 或 refreshCatalog，V8 报告它结束时的栈仍位于同一函数的 rethrow。此时正执行的 await 续体由 runner.query 返回的具体 Promise 触发。核对该续体中的原生错误帧、错误对象及两个请求的独立结果，可以把相同 SQL 和错误信息归回各自的调用行。
适用范围与局限
报告者的 Nest 应用、实体和真实表名未发布。程序使用其 Node 和 TypeORM 版本、SQL Server 驱动、查询方式和同类非空约束。两个入口以及查询返回、异常打印和 V8 结束时的观测点为本地对照。服务端事件独立验证错误与 SQL；未将具体服务端会话推作 JavaScript 的协程创建者。
