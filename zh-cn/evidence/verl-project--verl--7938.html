案例结论

本地复现结果
报告版本、verl v0.9.1 发布版和迁移后的 recipe 654568c 均复现了相同的时序问题。70 个 rollout 发布结果，训练侧取走 64 个，队列中剩 6 个。若先重置计数、再移除已完成的 Task，计数变成 76。上限为 70 时，处理器随后即使移除了这些 Task 也无法接纳新样本。报告者的补丁应用到发布版和 recipe 后，两种事件顺序均重置为 6，下一批均凑齐 64 条。两个版本都通过 14 项 CPU 检查。
CoroPerf 证据说明
两条完全相同的队列发布栈分别接回两个样本 Task，它们均由同一个处理 Task 创建。记录 2 的结果在重置前已被消费，已完成的 Task 仍被计入。记录 4 的结果仍在队列，已完成的 Task 也被计入。记录 5 将计数为 76 时的接纳暂停接回同一个处理 Task 的创建记录 0。
适用范围与局限
实验在单个事件循环中运行仓库中的派发、发布、队列和重置逻辑，用本地事件控制顺序并代表模型完成。Issue 已关闭，GitHub 标记为不计划处理。本地补丁覆盖旧版 recipe，替代它的 V1 训练器不在本次实验范围内。
