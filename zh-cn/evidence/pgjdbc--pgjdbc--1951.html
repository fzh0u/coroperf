拼接补回了什么

原生 JFR 显示 JDBC 钉住位置和虚拟线程自己的入口。用 JVM 线程 ID 拼回工厂采集的创建记录后，才能看到更早的 Quarkus 请求分派调用者。

先看协程执行栈，再沿拼接点追溯创建栈和更早的调用者。各栈块保留原有帧顺序。

案例结论

本地复现结果
通过报告评论作者公开的 Quarkus Todo 示例向真实 PostgreSQL 写入，2 批共 18 次 HTTP 创建均返回 201，独立 SQL 查询核对了已提交的数据行。Hibernate 的 pooled-lo 配置会在获取序列值时固定虚拟线程。
CoroPerf 证据说明
JFR pin 事件的同一条请求栈包含 TodoResource.create、SequenceStyleGenerator.generate、PooledLoOptimizer.generate 第 61 行和 pgjdbc 的套接字读取。带 ACC_SYNCHRONIZED 的帧只有 Hibernate 这一处，独立 JVM 监视器输出也在同一行标出 monitors:1。切换为 none 后，同一驱动和数据库会话仍然在 nextval 等待，目标 pin 消失。
适用范围与局限
复现评论者报告的 ORM 持锁路径。使用该评论者稍后公开的 Quarkus 3.3.2 示例、Hibernate 6.2.7.Final、pgjdbc 42.6.0 与 JDK 21.0.1；原部署和输入未公开。普通请求与显式延长数据库序列锁等待分别记录。JFR 提供虚拟线程身份和物理栈。补采使用 Quarkus 的原始虚拟线程工厂和 JFR，不改变分配器配置。
