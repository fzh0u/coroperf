案例结论

本地复现结果
实际 Mistral-Small-4 分词器有 1,000 个特殊 token，测试配置过滤其中 996 个。v0.30.0 和所核查的主分支上，两个调用 Task 都构建同一个扩展词法器结构。本地有界缓存让第一个调用构建，第二个调用复用。v0.30.0 的热态解析器构建耗时中位数从 71.5 毫秒降到 0.14 毫秒。
CoroPerf 证据说明
两条 _build_drop_info 执行栈相同。用实际 asyncio Task 将记录 2、3 分别接回导出与预览入口的创建记录 0、1。使用补丁并反转启动顺序后，唯一一次冷构建随新的首个调用者移动。
适用范围与局限
CPU 实验使用固定版本的解析器引擎、原始 Mistral 配置和分词器数据。工具调用事件和 token 过滤结果一致，包括两个解析器状态隔离，以及相同文本在不同 token ID 下的过滤。计时范围为热态解析器构建。Issue 仍开放，补丁在本地。端到端推理和服务吞吐尚待测量。
