拼接补回了什么

案例结论

本地复现结果
两条 RPC 使用同一个方法和相同载荷。报告中的 gRPC 版本在 asyncio Task 提交时仍有请求 ID，两个同步处理器在线程池里读取时都得到 None。提议的上下文复制改动可恢复该值。在两种构建中，工作线程栈和所查的 Task 诊断都没有显示两个拦截器路径。
CoroPerf 证据说明
CoroPerf 用实际执行的 WorkItem，把工作线程中的 read_request_id 接回 run_in_executor 下的创建栈。提交时，该 WorkItem 持有的处理器就是同一个服务端 Task 在 route_profile 或 route_inventory 中创建的对象。去掉处理器到 WorkItem 的边之后，仍能接回提交栈，但更早的拦截器路径消失。
适用范围与局限
原始报告已有独立复现。下方展示报告使用的 gRPC Cython 构建和 CPython 3.9.18 上的双请求受控实验，使用定向 Task 和 WorkItem 探针。上下文复制对照使用了未合并的提案。
