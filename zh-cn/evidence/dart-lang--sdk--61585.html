案例结论

本地复现结果
两个功能入口各自发起一个不等待结果的调用，执行同一条 Future.forEach 拦截器链。在 CInterceptor.onRequest 处，同一 SDK 上的两次 StackTrace.current 和 VM Service 栈视图均显示相同的代码位置。3.5.3 的异步栈停在 Future 循环，3.14.0 已能追到 testFuture。两个版本的栈都缺少原始功能入口。
CoroPerf 证据说明
绑定时，探针记录实际的 nextIteration 闭包和现场栈。执行拦截器时，用 Dart 的 identical 把当前 Future 监听器的回调与先前记录的两个闭包逐一比较，再拼接同一对象对应的创建栈。展示运行中，featureB 先到达拦截器，对应记录 1 → 2。第二次到达的 featureA 对应 0 → 3。移除回调匹配后，两条采样均无法归属。
适用范围与局限
这是 Linux x86-64 上使用 Dart SDK 3.5.3 和 3.14.0 的 JIT 复现。采集通过 VM Service 断点完成，SDK 回调保持原样。独立校验使用拦截器实例的单独记录。两批实验共验证 32 条拼接，分别交换发起顺序和第一个拦截器的放行顺序。
