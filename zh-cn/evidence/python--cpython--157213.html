案例结论

本地复现结果
在 CPython 3.14.3 中，gather 的一个子任务报错后，原生调用图仍把已经转去等待其他对象的 gather 调用者列为等待者。应用官方补丁后，这条过期边消失，后来直接等待该 Task 的调用者仍会显示。回调 Handle 被回收后，Task 栈、调试创建栈、协程起源和原生调用图都缺少两个原始发起者。
CoroPerf 证据说明
CoroPerf 先把 survivor 快照接回同一个 Task 的创建栈。dispatch 创建 Task 时正在执行的 Handle，把这条创建记录连到更早的 call_soon 提交栈，从而找回 launch_profile 或 launch_inventory。移除回调这条边后，两条记录都无法再区分原始发起者。
适用范围与局限
上游问题针对当前等待关系。发起者归属是在 Linux 上用两个发起入口和定向回调探针验证的。下方两条链使用同一 CPython 3.14.3 解释器，官方回移补丁应用于单独复制的 asyncio/tasks.py。
