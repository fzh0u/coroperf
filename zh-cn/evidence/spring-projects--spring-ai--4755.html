案例结论

本地复现结果
三个本地工具分别延迟 120、80 和 40 毫秒。原版和用 concatMap 的异步候选版都只让一个工具处于运行中，批次耗时约 242 毫秒。显式启用本地补丁后，并发上限为 2 和 3 时，耗时中位数分别约为 162 和 121 毫秒。回调按不同顺序完成，写回模型会话的工具结果保留原 ID、内容和顺序。
CoroPerf 证据说明
两个 overview 回调在同一条 Reactor 调度线程上拥有相同的执行栈。核对实际调度的 Runnable 和它持有的 Mono sink，可以接回各自的登记栈。再用通过 Spring AI ToolContext 传入的同一个 Batch 对象，接回各自的应用发起栈。目录请求沿 4 → 2 → 0 回溯，研究请求沿 6 → 3 → 1 回溯。反转请求发起顺序后，归属随之交换。
适用范围与局限
实验用 Spring AI Model 1.1.0 依赖编译 PR #4756 及其父提交中的实际工具管理器。模型回复和工具延迟由夹具提供。本地补丁应用在该 PR 的源码上，只对显式启用的独立工具批次使用并发。供应商流式路径和当前主分支的工具决策 API 不在这次运行对照范围内。Issue 和 PR 均开放。
