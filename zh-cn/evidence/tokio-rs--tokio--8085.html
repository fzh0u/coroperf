拼接补回了什么

物理热点栈和 Tokio 自带的 spawn 位置完全相同。根据实际 poll 区间拼回创建栈，可把同一个 CPU 被调用者分别连回 launch_profile 和 launch_inventory。

栈帧保留在各自的采集块中。拼接点表示两个采集块之间有可核实的关系。拼接栈里的实例标签取自该实例在本次采集中首次出现的记录号。

案例结论

本地复现结果
Tokio 1.54.1 的普通采集对照中，CPU 和 I/O 共用运行时时，从对端开始写到完成读取，6 次 Unix socket 读取的中位延迟为 107.924 毫秒。将同样的 120 毫秒 CPU poll 放到单独运行时后，6 次读取的中位延迟为 0.039 毫秒。
CoroPerf 证据说明
挂起后，两条发起路径的物理函数栈完全相同，Tokio 自带的 TaskMeta 也指向同一行 spawn。CoroPerf 根据实际 poll 区间确定采样属于哪个任务，再接回创建栈。两轮共 24 次观测均恢复了正确的 launch_profile 或 launch_inventory，反转执行顺序后仍然一致。采样本身未携带任务 ID 或实验分组。
适用范围与局限
这是对上游调度问题的本地受控改编，使用一个异步 I/O worker 和固定长度的 CPU 片段。对端开始写入到读取完成的差值用于近似读取调度延时。
