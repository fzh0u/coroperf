案例结论

本地复现结果
Flink 2.1.0 发布版 Task 组件的一次成功有界运行中，两个 invoke 分别抛出 OriginalFailure；受控清理逻辑以 CancelTaskException 调用 failExternally。两个 Task 最终都是 FAILED，但 failure cause 为空。异常发生时的物理栈完全相同，均缺少之前构造 Task 的两个应用入口。
CoroPerf 证据说明
标准 JDI 在构造函数退出时记录真实 Task 接收对象，再从异常栈找到同一对象。coroPerf 将每次失败接回该 Task 的构造记录，恢复 importBranch 或 refreshBranch。独立终点检查读取实际 Task 引用，在建图后核对两个映射。同次执行的原生 JFR 记录到两个原始异常和两个工作线程启动事件，但这些栈没有保留历史构造入口。
适用范围与局限
这是使用真实发布版 SDK、官方测试构造器及有界 shuffle 环境的 Task-only 应用扩展，不等同于生产集群或上游原应用。原生 JFR 已保留原始异常；coroPerf 增补历史创建入口归属。此前失败的试验断言单独保留。最终成功工作负载只执行一次，没有增加版本、顺序或重复矩阵。未验证修复版行为、生产开销或调度器层级祖先。
