2. StackExchange.Redis #3240

订阅连接握手为何停在 ConnectedEstablishing？

.NET / async state machines · Open · 根因尚未确证

阅读上游 issue

已有证据
一次 CI 在进程内模拟 replica 上停住。报告已解释该状态为何耗尽连接超时，但客户端还是模拟服务端调度造成停顿尚未确定，多次本地尝试未复现。
所读材料中的修复状态
两个引用提交涉及测试发现／准备，报告没有证明它们修复握手停顿；Development 未列修复 PR。
CoroPerf 可补充的证据
把握手、响应处理 Task 关联到同一连接代次，找出哪个未完成响应或 continuation 阻止结束。
需要采集的关系与事件
跨恢复的 Task token、interactive／subscription 连接身份、消息／响应及 pipe 所有权、模拟服务端派发和完成时间。
如何区分原因并验证
采集原进程内测试，对比正常与停住的连接代次，定位最早缺失的响应／派发，先区分模拟服务端与客户端问题，再谈修复。
尚未解决的前提
真实 Redis replica 不能替代这个复现。Task 创建关系不证明消息或 pipe 所有权，仍需资源观察及原始失败时序。
第一步
先取得精确 CI revision、测试和日志，保留后来 discovery 测试绕开的 pub/sub 路径。
