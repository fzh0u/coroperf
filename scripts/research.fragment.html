Optimized and stripped binaries

Drogon #2331 · Which request stalled in PostgreSQL?

Disassembly identified construction, actor, and cleanup paths in a stripped build. The SQL blocking stack alone leaves the owning request ambiguous. Observed transfer and activation bindings assigned all six fault samples. Retaining creation history recovered all six request origins.

The HTTP/PostgreSQL adaptation used two request entry points to call the same coroutine function. Instruction dataflow alone assigned zero of six fault samples.

LLVM code-generation benchmarks

These benchmarks form a separate set of assembly observations. Each entry reports a code path or layout comparison on local toolchains.

  • #148380. The stripped Clang 19 out-of-line build allocated a 24-byte coroutine frame and dispatched through the frame’s destroy slot. The path took 14.36 ns per iteration versus 2.15 ns in Clang 18. An inlined Clang 19 caller used an allocation-free path at 2.15 ns. Upstream issue ↗
  • #56972. Moving cleanup to the destructor embedded the Baz frame inside Bar in the runnable adaptation. Allocations went from three to two per iteration and median time went from 45.77 to 34.71 ns. Upstream issue ↗
  • #57852. Splitting grouped awaitables removed three allocations in a construction-only comparison. In the completed-result experiment, both groupings allocated three frames and splitting was slower. Upstream issue ↗
  • #64933. Stripped Clang 14, 18, and 19 builds all executed the final-suspend indirect tail transfer. Clang 18 alone executed an out-of-line await_suspend helper in each observed iteration. Upstream issue ↗
