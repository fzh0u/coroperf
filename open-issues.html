How to demonstrate faster diagnosis

Test whether CoroPerf supplies missing execution and resource history that reduces time to a validated cause. These candidates are opportunities to test that claim; no diagnosis speedup has been measured.

  1. Admission: retain the original GitHub revision, inputs and failure signature; inspect discussion and repair links. Record source-review dates. Move cases with an established cause or repair out of the first-root-cause queue.
  2. Fixture: reproduce the same failure with ordinary runtime diagnostics. If the original environment is unavailable or conflicts, record skipped and its reason; keep the candidate visible with that blocker.
  3. Evidence: preserve native diagnostics as the baseline; add CoroPerf identities, generations and required resource events on the same pinned workload. Check event loss and observer coverage, plus tracing overhead, before interpreting a missing event.
  4. Diagnosis comparison: give independent analysts the same incident and information budget, with ordinary evidence versus ordinary evidence plus CoroPerf. Hide known answers; counterbalance analyst/order assignments across cases to limit learning effects. Preserve timestamps and hypothesis histories.
  5. Success: time to the first cause supported by discriminating evidence and an unchanged regression test, then validate a cause-specific repair and healthy/error paths. Record incorrect hypotheses, extra collection rounds and timeouts; report preparation and collection time separately.
  6. Reporting: link raw artifacts, builds, workload and repair evidence. Report per-case times, unresolved trials and tracing overhead; calculate speedup only for comparable successful trials, alongside success rates.
