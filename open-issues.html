1. Asio #1720

Which event stops the last socket-write operation from completing?

C++ / stackless · Open · Root cause unconfirmed

Read the upstream issue

Existing evidence
A closed-peer writer hangs. A later upstream comment reports the same failure with callbacks and improvement with epoll disabled; handler and frame-lifetime traces already exist. These are partial results, not a confirmed root cause.
Repair status in inspected material
No repair PR is shown in the rendered Development section. A related issue and attached reproducers are not a verified patch.
What CoroPerf could add
Join the writer and reused child-frame generations to the specific write operation, then locate the first missing registration, readiness, completion or resume event.
Required observations
Frame generation; socket generation; operation/handler identity; epoll registration and readiness; completion, resume and cleanup order. Operation/reactor observers are additional work.
How to distinguish causes
Use one pinned affected build for the original, callback and backend controls. Check whether the pending operation remains queued or completed without a resume. Validate any eventual repair against the unchanged regression and success/error paths.
Unresolved prerequisites
Creation ancestry alone cannot explain lost reactor progress; callback failure argues against a coroutine-only cause. The original fixture/timeout and exact dependencies still need recovery.
First step
Recover the original fixture and pin Boost 1.88.0 / GCC 13.3 / Ubuntu 24.04 before collecting anything.

2. StackExchange.Redis #3240

Why does the subscription handshake stop in ConnectedEstablishing?

.NET / async state machines · Open · Root cause unconfirmed

Read the upstream issue

Existing evidence
One CI run stalled against a fake in-process replica. The issue explains why that state consumes the connect timeout, but leaves client versus test-server scheduling unresolved; repeated local attempts did not reproduce it.
Repair status in inspected material
Two referenced commits change test discovery/setup; the report does not establish them as a repair of the stalled handshake. No repair PR is shown in Development.
What CoroPerf could add
Connect handshake and response-processing Tasks to one connection generation and determine which pending response or continuation prevents completion.
Required observations
Task tokens across resumes; interactive versus subscription connection identity; message/response and pipe ownership; fake-server dispatch; completion times.
How to distinguish causes
Capture the original in-process test and compare successful and stalled connection generations. Locate the earliest missing response/dispatch; distinguish a fake-server fault from a client defect before a repair claim.
Unresolved prerequisites
A real Redis replica is not an equivalent reproduction. Task creation does not establish message or pipe ownership; resource observers and the rare failing schedule are still needed.
First step
Recover the exact CI revision, test and logs; preserve the pub/sub path that the later discovery test bypassed.
