Issue findings

Local observation
On Node 22.2.0, all three ordinary runs and all three runs with native async stacks enabled reported ENOTFOUND without the application’s read call on line 10.
What CoroPerf showed
In all three traced runs, CoroPerf matched the socket error to the rejection of the same read Promise and recovered its application call on line 10. In all three wrapped controls, AggregateError printed the same line.
Scope and limits
The report used Windows x64. The Linux x64 run used the same Node release, the local resolver, and a probe that returned the original Promise.
