Issue findings

Local observation
The reporter created 100 balances from 0.25 to 99.25. Each balance joined to four rows, and the left join matched none. All 400 rows fell into one group. The balances sum to 4975.00 before the join, so the answer is 19900.00. The two reported PyPI builds, stable 2.0.1 and the PR parent returned 1990000.00. The landed source returned 19900.00. Every build described its output as DECIMAL(38,2). Turning off any one of the three optimizer passes in the table, or disabling the entire optimizer, restored the expected sum. The reporter also supplied a TPC-H query. Its 1,500 customers, 100 suppliers and 25 nations produced 5,929 joined rows. Weighting each customer balance by its matching supplier count gave 26492209.10. SQLite independently returned 2649220910 integer cents.
What CoroPerf showed
The reporter cast the input to DECIMAL(15,2) before adding 0.25. The resulting balance column was DECIMAL(16,2). In the parent trace, FilterStatisticsOptimizer called into SumPropagateStats, which specialized sum to sum_no_overflow. Its bound signature changed from DECIMAL(16,2) → DECIMAL(38,2) to BIGINT → HUGEINT (segments 2 and 5). The expression still declared a decimal result. Under TryDoubleEagerPushdown, SetStateExport received the integer signature (segment 6). Finalization wrote the integer 1990000, the correct number of cents, into a HUGEINT vector. The cast then wrote 199000000 to the scale-two result vector (segment 11), displayed as 1990000.00. The landed fix preserved the decimal signature at export. Its finalizer wrote the same 128-bit integer 1990000 into a DECIMAL(38,2) vector (landed segment 11), which represents 19900.00. The parent also returned 19900.00 with partial aggregate pushdown disabled. That trace still saw the integer specialization. Direct finalization wrote the sum into a scale-two decimal vector.
Scope and limits
The fix was verified on the merged source build. All three published wheels tested here were affected. The reporter used Python on Windows. The local runs used Python wheels and source-built CLIs on Linux. One variation distinguishes the parent from the three wheels. With n.nk < 3 the parent inflated all four groups to 382000.00, 390000.00, 398000.00 and 820000.00. The wheels and landed source returned 3820.00, 3900.00, 3980.00 and 8200.00. The query has no ORDER BY, so the comparison uses the complete multiset. The TPC-H measurements use generated scale-factor 0.01 data. Native stack and vector observations cover 2.0.0, 2.0.1 and both source revisions. Each ran the minimal query, the pushdown-disabled control and the TPC-H query twice.
