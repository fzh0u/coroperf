Issue findings

Local observation
SQLGlot 30.32.0 translated the reporter’s MySQL timestamp plus two hours into SQLite DATE. SQLite returned 2024-01-01. The landed source and 30.33.0 returned noon on that date. The four-row control also crossed midnight and leap day. The affected builds returned the correct dates but lost the times on all three non-null rows.
What CoroPerf showed
The physical capture follows the affected call on one thread. Segment 1 records DATE as the generator’s actual function argument for HOUR. Segment 2 contains the emitted fragment. Segment 3 records the statement received by SQLite. The fixed capture shows DATETIME at each step. The unchanged landed test’s four literal subtests fail before the change and pass afterwards.
Scope and limits
The tracker supplies a SQL statement and omits the installed version. The two release wheels and immediate source pair were exercised with real SQLite and a Python datetime oracle. The trace captures synchronous Python frames and SQLite’s statement callback. The original MySQL server was not required to validate the stated arithmetic.
