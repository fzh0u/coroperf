Issue findings

Local observation
On aiostream 0.6.4 and the fix parent, the original example hit AssertionError on the first batch and consumed zero items. The merged fix and 0.7.2 delivered all 25 values in order in every stock and traced run.
What CoroPerf showed
smap created the async_processor coroutine and yielded it to base_combine. The failing assertion and native warning identify the same object and frame in CORO_CREATED state. The fixed path awaited the callback and iterated its return value. CoroPerf also found the smap allocation stack with its transparent --capture-unawaited mode on every affected run of the unchanged example. The fixed runs had no such warning.
Scope and limits
The reporter had already identified the assertion in the issue description. The archive includes the full local stacks. The extended origin count includes this never-started object. Timings use three prepared local processes per build and include process startup.
