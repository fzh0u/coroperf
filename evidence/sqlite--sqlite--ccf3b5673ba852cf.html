Issue findings

Local observation
The original query returned 24 rows. SQLite 3.36.0 and the parent of the fix returned 17 incorrect strings. The eighth began with 50. A fresh aggregation of the same window began with 4450. Both the fixing commit and 3.37.0 returned all 24 expected rows.
What CoroPerf showed
GDB followed one statement from groupConcatInverse to the next result. The parent removed ten bytes, using the length of George for the separator after the outgoing value. The stored separator at that position was John. The fix removed eight bytes and preserved the next value. PostgreSQL string_agg and an independent Python calculation confirmed the expected output.
Scope and limits
The Linux CLI included SQLite’s generate_series implementation. The original query ordered by name alone. Adding a numeric tie-breaker reproduced the same discrepancy. The captured native stacks cover synchronous C execution.
