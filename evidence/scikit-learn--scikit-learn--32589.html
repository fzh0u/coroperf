Issue findings

Local observation
On scikit-learn 1.7.2 the reporter’s unseen building type, casino, encoded as [0, 0] under warn. The same encoder settings with infrequent_if_exist returned [0, 1]. Both modes returned [0, 1] on 1.8.0.
What CoroPerf showed
At the call to _map_infrequent_categories, the caller had already selected the effective policy infrequent_if_exist. With the instance policy still set to warn, the old function assigned code 2 and left the row masked out. The fix kept that code and marked it valid. With a fitted linear model on separate CSV data, that single feature changed the prediction for an unseen building use from 10 to 38.
Scope and limits
The local Linux run matched the report’s CPython 3.13.3 and numerical package versions. The reporter used Windows. The parent and fix comparisons used their exact encoder module on the same 1.8.0 wheel. The CSV rates are controlled inputs. This synchronous path has no coroutine origin.
