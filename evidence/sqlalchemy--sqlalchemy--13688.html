Issue findings

Local observation
On 2.1.5, async deduplication yielded [1,1,2], selecting column b returned values from a or exposed both columns, and an ORM query still demanded unique(), while synchronous results were correct.
What CoroPerf showed
scalars() and mappings() inherited the underlying result’s columns and uniqueness policy instead of the wrapper’s state. Reversing the deduplication order worked, and both upstream test suites improved from one of six passing to all six. The separate coroutine replay matches that same all() allocation and return frame. The affected instance returns the a column where the caller selected b.
Scope and limits
The workload uses the original SQLite example. The allocation probe wraps the call to all() and returns the existing coroutine object. Stock and traced results agree on every build.
