Issue findings

Local observation
The two reported SQL queries used 19:00:00 and 19:00:30 on December 31, 1969. Both lost 30 seconds at the parent revision. Among 6,347 historical USGS earthquake times, the same build misclassified all 11 events on a 30-second boundary. It also misclassified all 88 events on a one-second boundary. The fixed CLI matched integer floor division for every event.
What CoroPerf showed
At an exact negative boundary, the remainder is zero. GDB observed compute_distance subtract an extra stride on the parent and keep the original delta on the fix. The two posted constants reached this code during optimizer constant folding. An actual earthquake row reached it during physical projection. For that row the reader’s spawn stack, allocated Tokio task ID and header address match the poll that executed the incorrect branch on a worker thread.
Scope and limits
The report supplied SQL without a binary version. The local runs compare the upstream fix with its direct parent in unmodified Linux/amd64 debug builds. The earthquake catalogue and the nanosecond controls are additional workloads. The verified task origin belongs to the physical record-batch scan. The two literal queries were evaluated on the CLI main thread.
