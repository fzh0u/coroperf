Issue findings

Local observation
The reporter's five chunks carry three data lines belonging to a single event. The fix parent emitted two callback values: the first contained A and B on separate lines, and the second contained C. The fixed parser and native Chromium EventSource emitted one value with A, B and C on three lines. The old and fixed parsers both produced one event when receiving the same 28 bytes in one chunk.
What CoroPerf showed
The parent completed the B line when its chunk ended in CR. The following LF became an empty line and triggered early dispatch. The fix retained the B line and its CR until the next chunk supplied the LF. V8 recorded both line-splitting results and the exact pending data at dispatch. Two of the 27 possible single cuts of the reported payload changed the parent's output. All 27 produced the expected value on the fix.
Scope and limits
The original program feeds text chunks directly. The HTTP and browser runs are separate local controls. The Node client records the exact text chunks passed to the library; native Chromium exposes only dispatched events. Its extra named completion event terminates the browser control. The library parser runs synchronously inside a Web Streams callback.
