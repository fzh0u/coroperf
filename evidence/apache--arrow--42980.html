Issue findings

Local observation
For [[0, 1], None, [2, None, 3]], the old footer reported one null and five non-null values instead of two and four. Both versions read back all three rows with the same minimum and maximum.
What CoroPerf showed
The old calculation subtracted four non-null values from five leaf slots, overlooking the outer None. The fix used all six level entries, and replacing the outer None with [None] also corrected the old count.
Scope and limits
Checked column-chunk statistics and decoded values, with synchronous native stacks. Query pruning was untested.
