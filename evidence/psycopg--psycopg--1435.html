Issue findings

Local observation
Psycopg3.3.6/CPython3.13.5/pure-Python libpq18.7/private PostgreSQL18.7 runs one original timing-sweep batch and stops on its first matching error, at trial2. Trial1 returns CancelledError; trial2 receives2cancel calls but ends with OperationalError: cannot exit pipeline mode while busy. The matching Task has cancelled()false/cancelling()2, and the connection remains in pipeline mode(status1). Native traceback shows cancellation followed by cleanup failure and executemany rethrow. Targetexit0, connections closed, table dropped and private server shutdown. New-batch setup/run79.84s; earlier socket startup failed before any target and is archived.
What CoroPerf showed
The API-returned Task [address] matches CoroPerf generationg3. Creation25 joins cancellation27 and pipeline cleanup OperationalError36, restoring launch_update_batch, absent from native error traceback, completed Task error stack and current.folded. The same Task exits with exception; all14 focused observations are attributed. Explicit API observation26 binds the actual Task/Connection/Cursor within trial2. Connection address [address] and the underlying coroutine object address were reused between the two trials, while the Task runtime identities remain distinct. The earlier Task is excluded, so address equality is not misread as shared connection ownership. The report already explains cleanup masking cancellation; added diagnostic evidence is the exact operation and its historical submitter at both phases.
Scope and limits
One upstream batch with2trials, stopped immediately at the first matching error; no400trial distribution, further timing trials, alternative version/implementation or fix comparison. Locally2cancel calls are observed, not the report's exact three-cancellation sequence; exception propagation observations are not distinct exception-object counts. The original victim Task,1000-row table,two UPDATE parameters and delay/gap schedule remain; the helper only names the existing create_task expression. Extra API observations supply resource associations within the matching trial; generic ancestry cannot infer resource ownership, cross-trial object lifetime or cancellation initiator. Harness helper names are not unknown production caller names. Full Chancy worker retry/shutdown behavior is unverified. Report gives PostgreSQL18 without a patch; local18.7 is explicit.
