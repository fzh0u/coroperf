Issue findings

Local observation
The six-row program from the issue asks for the cumulative sums of ones and twos. Dask 0.18.1 returned the name ones and values 1, 2, 1, 2, 1, 2 twice. On 731 days of bike rentals, all 731 registered-rider totals were wrong when casual riders were requested first. Reversing the arguments reversed which column was lost. Computing the columns separately returned the correct totals.
What CoroPerf showed
The captured _GroupBy._cum_agg calls assign identical output task names to the two columns. During dask.compute, _unpack assigns both to slot 0 and retains the first collection. The merged graph has one output. Separating only the output names restored both slots but exposed a second collision in the carry tasks. On February 13, the casual-rider calculation added 397 to the registered carry of 16,932, returning 17,329. The correct casual carry was 1,443. The upstream fix distinguishes both sets of names. Its results match independent integer sums in all 15 settings.
Scope and limits
The reporter supplied the six-row program and did not name a Dask release. We selected releases on either side of the fix and added the UCI Bike Sharing daily dataset to test partition boundaries. The captures show synchronous Python calls. The coroutine-origin count is unchanged.
