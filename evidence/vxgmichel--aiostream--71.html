Issue findings

Local observation
When the two posted iterators failed together, the consumer received one exception and asyncio warned about the other. Staggering the failures produced only the consumer exception.
What CoroPerf showed
wait_any returned both completed tasks, but cleanup removed the second without reading its exception. The fix calls exception() on that same task, clearing the unread flag.
Scope and limits
The report omitted the version. Task and exception identity came from instrumented runs. Plain runs kept asyncio’s default exception handler.
