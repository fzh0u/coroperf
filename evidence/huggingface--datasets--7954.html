Issue findings

Local observation
The reporter interleaved three datasets of lengths 3, 4, and 3 without replacement. Datasets 4.5.0 and the fix parent returned nine values, omitting 13 from the second dataset. The fix commit and release 4.6.0 returned all ten in order. On 344 Palmer Penguins records grouped by species, the affected loader delivered 204 records. It omitted 84 Adelie and 56 Gentoo records. The fixed loader delivered all 344, in the order independently reconstructed from the CSV.
What CoroPerf showed
The captured call to _interleave_map_style_datasets shows how the rows disappeared. With no sampling probabilities and the all_exhausted_without_replacement strategy, the affected code used the shortest input length to build the selection indices. It selected three rounds from the reported example. The fix added a fourth round for the second input alone. In both runs, the indices stored in the returned Arrow dataset matched the indices selected by that function.
Scope and limits
The result applies to round-robin interleaving of map-style datasets with unequal lengths. Equal-length inputs and the seeded weighted control retained every record on all four builds. The captured selection ran synchronously. Separate PyTorch runs with zero and two loader workers confirmed batch delivery on both sides of the fix.
