Issue findings

Local observation
The reporter called a Prefect task that returns len(frame) with two zero-column DataFrames and a copy of the second. Their row indexes were [1, 2], [3, 4, 5] and [3, 4, 5]. With persisted results and the INPUTS cache policy, the reported checkout, 3.9.3 and the fix parent all returned [2, 2, 2]. Only the first call executed the task body. The landed fix and 3.9.4 returned [2, 3, 3], executing both distinct inputs. Adding one column of ones gave [2, 3, 3] and two body executions on every build. A separate two-row task returned the index labels themselves. When the labels changed from [1, 2] to [3, 4], the three affected builds returned [1, 2] again. With two-level indexes they likewise returned the old labels [(a, 1), (b, 2)] for [(a, 3), (b, 4)]. Both corrected builds returned the changed labels, and all five passed the populated-frame label control. Nine upstream regression cases also passed on the landed revision.
What CoroPerf showed
Prefect's DataFrame transform retained column names and their Series. With zero columns both lists were empty, so different row indexes produced the same hash input. On the reported checkout the legacy hashing module encoded plain JSON and produced 50d1743b8e3cb8d91a3767afb7293aff. The 3.9.3 wheel and the PR parent hashed a zero byte followed by JSON with a tuple tag, producing be9919c1b8b78f044eb31bb2a55eee9d. The landed transform includes the actual Index for a zero-column frame. In the async replay of the three-row call, the engine coroutine created by run_task at task_engine.py:1986 (segment 15) was on the physical Inputs.compute_key stack when the shared key returned (segment 19). Prefect found the two-row result on disk. At task_engine.py:1722, call_task_fn executed “result = await transaction.read()”. CPython recorded the read coroutine before its first await (segment 25). Its identical frame returned the stored record with value 2 at transactions.py:475 (segment 29). The fixed trace retains [3, 4, 5] in the key input and reaches the row_count body, which returns 3 (segment 25 of the landed graph).
Scope and limits
The posted program is synchronous. Each of the five builds ran it directly and in two instrumented trials on Linux x86-64 with pandas 2.3.3. The reporter used macOS arm64. The coroutine captures come from a separate public async task with the same inputs and cache policy. In the cross-process experiment, six fresh interpreters per source revision shared one local Prefect server. Each input order had private result storage and used JSON serialization. The third worker hit the cache in all four sequences. Every byte in its result directory was identical before and after the call.
