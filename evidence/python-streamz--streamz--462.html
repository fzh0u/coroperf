Issue findings

Local observation
A generator containing the integers 0 through 9 produced no downstream values on 0.6.4. After the exception, 1 through 9 were still in the generator. The merged fix and 0.6.5 delivered all ten. In a separate SQLite pipeline, each fixed input path delivered all 344 Palmer Penguins records in the expected order.
What CoroPerf showed
The exception stack stopped at flatten.update after it read item 0. The next expression called len(x) to decide whether this was the last item. A generator has no length. A SQLite cursor reached the same line while a list of the identical rows passed. The fix reads one item ahead to identify the last one. In one- and three-record batches, the fixed generator path attached the year marker to the last record of each batch.
Scope and limits
The posted program uses a synchronous Stream. The task-origin evidence comes from a separate pipeline using the built-in asynchronous from_iterable source. Source.start registered its run callback. Tornado scheduled the task that later reached flatten.update. The capture identified the generator, cursor and list source tasks separately. The reporter’s traceback identified Python 3.10 and did not specify a Streamz release.
