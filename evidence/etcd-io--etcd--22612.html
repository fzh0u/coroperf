Issue findings

Local observation
After c, b and a were created in that order, etcdctl returned c, b, a for the unlimited creation-order query. A limit of one returned b on the reported revision. Explicit ascending order returned c. In a 412-invoice workload the earliest invoice was 0001 from Germany. The same limited query returned invoice 0119 from Argentina.
What CoroPerf showed
The gRPC server created the observed stream goroutine at go f(). The trace follows that instance into rangeLimit, where a request for one selected a two-key storage read. The storage scan produced a and b. Sorting those candidates put b first, after c had already been excluded. The proposed change resolved the default sort direction before choosing the read limit. It read all three keys and returned c.
Scope and limits
The original workload ran on a single voter. The two three-voter clusters are an additional comparison with unique sort values at revision 431. Each cluster served 60 reads per voter. The Go trace probes observed one invocation of the original limited query on each source build. The source comparison uses the branch linked by the reporter.
