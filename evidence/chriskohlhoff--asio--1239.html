Issue findings

Local observation
Both timer resumptions have the same physical function stack in symbolized GDB. Asio's caller_ links reach async_b and then the co_spawn_entry_point, whose caller link is null. Handler tracking reports the shared library submission and timer operations.
What CoroPerf showed
From the stripped executable, registers and stack bytes, CoroPerf uses instruction dataflow to identify the live async_c frame. It joins the sample to async_c construction, then follows its observed creator to the creation stack of async_b. The earlier stack recovers launch_profile or launch_inventory on all eight samples across four trials, including reversed launch order.
Scope and limits
The timer adaptation uses GCC 11, Boost.Asio 1.83 and Linux x86-64. The probe locations are selected for the test and the recovered PCs receive function names after reconstruction from the matching debug ELF. The upstream application ran on macOS arm64.
