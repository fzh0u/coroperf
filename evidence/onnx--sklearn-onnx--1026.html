Issue findings

Local observation
The reporter trained a random forest on six rows, using two categorical columns and two numbers. With min_frequency=2, scikit-learn put CAT2 values a, b and c into one rare-category indicator and gave d its own column. The 1.15.0 and 1.16.0 converters and the parent of PR #1029 produced separate columns for all four CAT2 values. ONNX Runtime on CPU therefore passed eight columns to a forest trained on six. The original unseeded program printed different labels after conversion on each of those three builds in both recorded trials. With seed 17 they all changed five of the six labels. The merged source and 1.17.0 each produced six columns, matched all six labels and kept the largest absolute class-probability difference below 0.000001. In a separate control, retraining with the default frequency setting gave both pipelines eight columns and identical labels on every build.
What CoroPerf showed
On 1.15.0 the converter received the fitted encoder (segment 6) and passed [-1, 6] to the categorical Reshape (segment 17). Appending the two numeric passthrough columns put them at positions 6 and 7. The forest reads positions 0 through 5, so its splits on positions 4 and 5 received indicators for CAT2=c and CAT2=d. On the merged source each encoder split its frequent and rare indicators and summed the rare group. For CAT2 the split sizes were [1, 3]. The categorical Reshape then used [-1, 4] (comparison segment 47). The intermediate shape calculator reported six categorical columns on both builds. The emitted Reshape and the CPU tensor read at the forest input establish the widths that inference actually used. Extracting TreeEnsembleClassifier from each of the five saved trial-one pipelines yielded identical node bytes. Feeding the correctly grouped tensor directly into that forest recovered all six sklearn labels. A separate traversal of the 100 serialized trees checked both possible input layouts. In two held-out rows with categories (a, d), changing the numeric pair from (0.36, 0.85) to (0.54, 0.57) left the affected pipeline’s class-1 probability at 0.32. The same forest given the grouped features returned 0.37 and 0.88.
Scope and limits
The issue is open and the reporter omitted a converter version. 1.15.0 was the latest wheel at the time of the report. PR #1029 came from branch i1026 and its description refers to earlier PR #1028. The adjacent source runs locate the grouping change at #1029, and 1.17.0 was its first release. The parent and merged comparisons used full Git packages, both labeled 1.17.0 internally. All five ran with scikit-learn 1.3.1 and ONNX Runtime 1.17.3 on CPU. The reporter’s classifier used random training, so the first table gives the wrong-label count separately for each original run. The reproducible label and probability comparisons use a separate seed-17 fit. The ten-row forest-input experiment reuses those fitted trees on the six posted rows and four held-out rows. Its second table shows class-1 probabilities rounded to two decimals. CPython sampled synchronous converter calls. The ONNX tensors and predictions came from actual CPU executions. This case contributes zero coroutine origins.
