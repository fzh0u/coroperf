Issue findings

Local observation
The actual Mistral-Small-4 tokenizer has 1,000 special tokens, 996 filtered by the tested parser configuration. On v0.30.0 and the checked main revision, both caller Tasks construct the same augmented lexer shape. The local bounded cache builds it for the first caller and reuses it for the second. Median warm parser construction on v0.30.0 drops from 71.5 ms to 0.14 ms.
What CoroPerf showed
The two _build_drop_info execution stacks coincide. Matching the actual asyncio Task connects observations 2 and 3 to the separate export and preview launch stacks at records 0 and 1. With the patch and reversed launch order, the one cold build follows the new first caller.
Scope and limits
The CPU replay runs the pinned parser engine, original Mistral configuration and tokenizer data. Tool-call events and token filtering agree, including separate state for concurrent parsers and different token IDs for shared text. The timing covers warm parser construction. The issue is open and the patch is local. End-to-end inference and serving throughput remain unmeasured.
