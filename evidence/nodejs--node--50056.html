Issue findings

Local observation
On Node 24.18.0, 603 profile-only samples from three controlled runs showed the sharedService → busySpin path without either application launcher. Both callers had samples in every run.
What CoroPerf showed
CoroPerf assigned 579 profiled observations to the active runtime generation using the observed async-hooks enter/leave interval. Joining each observation to creation recovered launchProfile or launchInventory. Independent fixture timing and request labels agreed for all 579 samples, including the run with reversed execution order.
Scope and limits
This is a two-caller adaptation of the missing asynchronous ancestry problem, using V8's CPU profiler on Linux. The report's fast-blocked-at watchdog and Node 20.5.1 environment were not replayed. Counts measure attribution, not collection overhead or production performance.
