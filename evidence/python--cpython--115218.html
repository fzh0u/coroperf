Issue findings

Local observation
Two readers wait at the same read_payload site. cProfile reports one function entry with four calls and about 0.5 ms of cumulative execution in the representative stock run. CPython 3.15.2 async-aware wall sampling sees the pending readers as distinct Tasks with 65 and 245 samples. Both Task creation traces reach the shared dispatch callback. Neither the sampled await chains nor the creation traces identify the original launchers.
What CoroPerf showed
The capture times each suspension and resumption on the same Task and actual StreamReader Future. At Task creation the observer matches the exact Handle running dispatch to its earlier scheduling stack. Records 0 → 2 → 4 connect 65.9 ms to launch_inventory. Records 1 → 3 → 5 connect 245.6 ms to launch_profile. Without the Handle edges, the timed observations reach only the shared dispatch.
Scope and limits
The experiment uses local socket pairs on Linux with CPython 3.10.4 and 3.15.2. An independent sender releases identical payloads after two different delays. Two batches verify 32 attributions with launch order and delay assignment varied independently. Each duration measures one Task's suspension, including any time before it resumes after readiness.
