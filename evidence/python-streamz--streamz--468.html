Issue findings

Local observation
Two releases and the fix’s parent created ten callback coroutines without starting any, producing ten warnings. The merged version printed all ten single-item tuples in order.
What CoroPerf showed
sink.update created each coroutine and _emit returned it, but flush cleared the buffer without awaiting it. The merged fix clears first so a value of 13 emitted by a callback survives for the next batch. The transparent CoroPerf launch identified all ten allocations in each affected run. The stock warning showed the point where the coroutine was discarded. The captured allocation stack included sink.update, _emit and flush.
Scope and limits
The report omitted a version. CPython creation records identify the unstarted coroutines separately from scheduled tasks.
