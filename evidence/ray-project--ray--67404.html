Issue findings

Local observation
The second caller sent a=2 and b=20. The completed deployment handle returned a=20 and b=2 on the reported nightly. In a two-feature Iris classifier, mixed keyword order reversed 30 of 60 held-out feature pairs and changed 16 predicted species. Accuracy fell from 56 to 44 correct. Two independent runs agreed, with profiling on and off.
What CoroPerf showed
The create stack reaches _BatchQueue._process_sub_batches as it starts an asyncio task. The execution stack reaches _batch_args_kwargs inside the same live _process_batch_inner coroutine. The recorded inputs were [a, 1, b, 10] and [b, 20, a, 2]. The merge took the keys from the first request and grouped values by position, yielding a=[1, 20] and b=[10, 2]. The observer matched the task, coroutine and executing parent frame for all 95 batches per traced actor. With the proposed change, both requests reached the merge in declaration order.
Scope and limits
The reporter used Windows. These runs used Linux x86-64, the same nightly commit and CPython 3.13.4. The comparison substituted the batching module from proposed PR #67405. The classifier exercises two named features from the UCI Iris dataset. Its correctly bound baseline classified 56 of 60 flowers correctly.
