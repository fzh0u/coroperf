Issue findings

Local observation
With a minimum frequency of five, the reporter’s 100-row program trained an encoder in which all 47 known categories shared code 0 on the saved draw. For the first input, 22, scikit-learn returned 0 and the ONNX model from skl2onnx 1.19.1 returned 12. Across the 100 rows, 87 codes were wrong. The seven literal inputs in a later issue comment reproduced all of its printed values, including six incorrect ONNX codes. Release 1.20.0 produced the expected codes for both programs.
What CoroPerf showed
The parent converter passed sorted category indices 0 through 46 to the ONNX LabelEncoder. Its fitted estimator already held 47 zeros as the frequency-group mapping. The fix passed that mapping to the node. The converter stack, serialized node attributes and CPU inference results agree. In the Auto MPG control, two rare cylinder counts shared code 3. Grouping also renumbered ordinary four-, six- and eight-cylinder categories, which explains why every held-out vehicle received an incorrect code on 1.19.1.
Scope and limits
The original program supplied neither random seeds nor installed versions. Its published sample had 86 discrepancies. The local runs execute the unchanged program with seed 1215 and save the exact 70-row training split. Both releases and both source revisions use the same CPU backend. The 80-row Auto MPG holdout is independent of fitting. The per-cylinder table also scores the complete 398-row public file to cover rare cylinder counts present only in training. The Python stacks cover synchronous conversion and the inference API. Native operator profiles come from separate executions of the saved models.
