Issue findings

Local observation
The reporter sorted xb, ya and zc and then removed the first character with str.slice(1). All four releases returned [b, a, c]. Polars 1.43.0 and the reported 1.43.1 release marked them as ascending. Series.min() and a one-group minimum both returned b, and DataFrame.sort() left the rows in place. Polars 1.43.2 and 2.1.0 cleared the flag, returned a, and sorted the rows as a, b, c. In the reporter’s tail example, the last two characters of ab, abc, b and ba are ab, bc, b and ba. The affected maximum was ba and the correct maximum was bc. Taking the first character preserved order in both directions on every build. In the separate SQL test, 16 of 192 queries disagreed with SQLite, all on the two affected releases. The materialized fruit suffixes gave minimum pear and maximum fig. SQLite returned apple and plum.
What CoroPerf showed
The 1.43.1 native substring function returned [b, a, c] with its ascending flag still set (segment 11). The string min_reduce read flag word 1 on the same Arrow array and view buffer (16). It took the ascending branch (18) and selected b at index zero (19). In the 1.43.2 comparison the scalar slice cleared the order bits (11). The reducer read word 0, entered its scan and returned a (25). In a separate experiment, importing the affected series through the public Arrow stream reused the same 48-byte string-view buffer. Both exports were held open during the address comparison. The imported series had neither sort flag and returned a. The list reconstruction and disk IPC round trip agreed. PR #28573 clears the order bits for a scalar nonzero-offset slice or a scalar tail and retains them for a zero-offset prefix.
Scope and limits
The reporter used macOS arm64. The wheel runs used Linux x86-64, with the same CPython 3.14.6 and UInt32 index type. Separate Rust executables called public polars-core and polars-ops 0.54.4 methods at parent 72c95bfad0 and merge 36e414b4cb. On the reported examples the parent matched the 1.43.0 and 1.43.1 wheels, and the merge matched 1.43.2 and 2.1.0. For a second suffix sequence [c, b, a], the parent returned minimum c and maximum a. The merge returned a and c. GDB sampled str_slice calling substring, min_reduce reaching min_str, max_reduce reaching max_str, and Series::sort in both executables. SQL results and plans came from separate processes. On these two tables the optimized single-statement MIN/MAX plan applied str.slice directly to the source with no SORT node. The materialized MIN/MAX plan scanned the frame [id, k]. All single-statement, prefix and LIMIT 1 controls matched SQLite. The Series minimum diagnosis comes from synchronous native execution. These runs contribute zero coroutine origins.
