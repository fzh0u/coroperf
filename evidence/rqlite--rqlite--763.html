Issue findings

Local observation
Three healthy nodes committed writes and reported indexes 9 and 12. The affected status endpoint returned both as JSON strings. Taking their maximum with jq returned "9". With the upstream fix it returned the number 12. Across 24 responses per build, the parent sent all 216 selected numeric field values as strings. The fixed build sent all 216 as numbers.
What CoroPerf showed
The Go stack linked the status handler to Store.Stats. The returned Raft map already held the strings seen in the HTTP response. The fix converted numeric entries before JSON encoding. We independently decoded each node’s durable log and replayed the SQL. The on-disk snapshot at index 32 contained the same 24 rows on all three nodes.
Scope and limits
The report describes the field type and provides no reproduction script. The replay used the upstream command examples and the exact parent and fix revisions. The three-node workload, snapshot threshold of 32 and jq check are local controls. The recorded call stacks identify the status path. A goroutine creation site was not established.
