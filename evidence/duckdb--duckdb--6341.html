Issue findings

Local observation
With two timestamps on the left and a new empty table on the right, the reported DuckDB build returned zero rows for both < and >. Equality returned the expected two rows with nulls. The fix returned both rows for all three comparisons. With 12 earthquake records, both affected comparisons omitted all 12.
What CoroPerf showed
The captured native stack reached StatisticsPropagator while optimizing the comparison join. EXPLAIN showed a cross product on the parent. Disabling statistics propagation alone restored the left join and both rows. The old optimizer treated the comparison as always true and rewrote the outer join to a cross product. A cross product with an empty table returns zero rows.
Scope and limits
The native sample identifies the optimizer branch. The operator rewrite is inferred from the plan, the single-optimizer control and the parent-to-fix change. The tests also covered a populated right input and an input emptied by deletion. The synchronous C++ engine contributed no coroutine origin.
