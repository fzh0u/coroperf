Issue findings

Local observation
The reporter ran etcdctl member list --hex -w json on 3.5.1. We repeated the command against three local etcd members, transferring leadership with move-leader to reach each sampled term. At term 11 the client exited successfully and wrote the bare letter b. A JSON reader rejected the output at that letter. At term 16 the same client wrote 10. The reader accepted the entire document and returned the integer ten. The gateway returned 16, and all three members agreed on term 16 before and after the reads. Both behaviors followed the client when the server version changed. Across 6 primary clusters and 336 completed member-list calls, all 168 plain JSON reads returned the cluster term. With --hex, 42 outputs failed to parse, 28 parsed to the wrong integer and 98 agreed with the cluster. Term 9 was a useful control because both bases printed 9.
What CoroPerf showed
Hardware breakpoints caught the member-list command calling (*jsonPrinter).MemberList, then printMemberListWithHexJSON, then strconv.AppendUint. At term 16 the response header in the 3.5.1 client already held 16. At printer_json.go line 70 the formatter received 16 and base 16, and its returned bytes spelled 10. The separately run stock client printed those same bytes. At the same term the 3.5.3 client passed base 10 and returned the digits 16. At term 11 the two conversions returned b and 11. Only raft_term used the wrong base. All 80 observed conversions of identifiers used base 16. The two header IDs and the three membership IDs were correctly quoted hexadecimal strings, and each decoded to the ID returned by the gateway. The published stacks use term 11. Segment 1 records the header at printer entry, segment 6 records the formatter arguments, and segment 7 records the returned byte slice. The second table gives both terms for the release and backport clients. For the stripped release binaries, the recorder resolved the sampled addresses using the executable’s own Go function and line tables. The source-built pair also provided named debug arguments for a second check of the value and base.
Scope and limits
The affected releases tested were 3.5.1 and 3.5.2. Release 3.5.3 is the first corrected 3.5 release tested, and 3.6.0 also agreed with the gateway. PR #13711 changed the main branch. The executed source boundary was its 3.5 backport, PR #13727, from 1eb8b6a75c to 3c2ef71358. The official 3.5.1 Linux server identified itself as e8732fb5f. Its printer source and the printer at the 3.5.1 tag (d42e8589) have the same Git blob. The primary matrix read the member list from one endpoint per cluster and checked status and health on all three. The additional observer clusters used 3.5.1 and 3.5.3 servers at terms 11 and 16. The debugger captured 208 physical stops across 16 client invocations. The stacks cover 3.5.1, 3.5.3 and the two backport builds. Evidence for 3.5.2 and 3.6.0 comes from stock CLI output. The samples show synchronous client calls and supply zero matched goroutine origins.
