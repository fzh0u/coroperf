Psycopg #1435 · 取消被pipeline清理错误替换

原生结果、Task/资源身份及限制 · 中文案例

Psycopg3.3.6/CPython3.13.5/pure-Python libpq18.7/private PostgreSQL18.7 runs one original timing-sweep batch and stops on its first matching error, at trial2. Trial1 returns CancelledError; trial2 receives2cancel calls but ends with OperationalError: cannot exit pipeline mode while busy. The matching Task has cancelled()false/cancelling()2, and the connection remains in pipeline mode(status1). Native traceback shows cancellation followed by cleanup failure and executemany rethrow. Targetexit0, connections closed, table dropped and private server shutdown. New-batch setup/run79.84s; earlier socket startup failed before any target and is archived.

Psycopg3.3.6、CPython3.13.5、纯Python libpq18.7和私有PostgreSQL18.7一次运行原始时序扫描批次，在第2个trial首次匹配错误后立即停止。第1个trial返回CancelledError；第2个收到2次cancel，却以OperationalError: cannot exit pipeline mode while busy结束。对应Task的cancelled()为false、cancelling()为2，连接仍处于pipeline模式(status1)。原生回溯显示取消后清理失败，executemany再抛出。目标退出0，连接、表、私有数据库均清理。新批次含准备运行79.84秒；此前socket启动失败发生在目标前，日志已存档。

The API-returned Task 0x7b3b4dcf7490 matches CoroPerf generationg3. Creation25 joins cancellation27 and pipeline cleanup OperationalError36, restoring launch_update_batch, absent from native error traceback, completed Task error stack and current.folded. The same Task exits with exception; all14 focused observations are attributed. Explicit API observation26 binds the actual Task/Connection/Cursor within trial2. Connection address 0x7b3b4dd08550 and the underlying coroutine object address were reused between the two trials, while the Task runtime identities remain distinct. The earlier Task is excluded, so address equality is not misread as shared connection ownership. The report already explains cleanup masking cancellation; added diagnostic evidence is the exact operation and its historical submitter at both phases.

API返回的实际Task 0x7b3b4dcf7490与CoroPerf代次g3匹配。创建25分别接到取消27、pipeline清理OperationalError36，恢复原生错误回溯、已结束Task错误栈和current.folded都缺失的launch_update_batch。同一Task以异常退出，聚焦14个观察均归因。额外API观察26在第2个trial内记录实际Task/Connection/Cursor。两个trial复用了Connection地址0x7b3b4dd08550及底层协程对象地址，但Task运行时身份不同；分析排除了前一个Task，没有把地址相等误当作共享连接所有权。报告已说明清理掩盖取消，新增诊断证据是两阶段的实际操作及历史提交入口。

One upstream batch with2trials, stopped immediately at the first matching error; no400trial distribution, further timing trials, alternative version/implementation or fix comparison. Locally2cancel calls are observed, not the report's exact three-cancellation sequence; exception propagation observations are not distinct exception-object counts. The original victim Task,1000-row table,two UPDATE parameters and delay/gap schedule remain; the helper only names the existing create_task expression. Extra API observations supply resource associations within the matching trial; generic ancestry cannot infer resource ownership, cross-trial object lifetime or cancellation initiator. Harness helper names are not unknown production caller names. Full Chancy worker retry/shutdown behavior is unverified. Report gives PostgreSQL18 without a patch; local18.7 is explicit.

一次上游批次含2个trial，首次匹配错误后停止；无完整400次分布、后续时序扫描、其他版本/实现或修复对比。本地记录2次cancel，不断言报告的精确三次取消顺序；异常传播观察数量不代表异常对象数量。保留原victim Task、1000行表、两个UPDATE参数及delay/gap顺序；辅助函数只给原create_task表达式命名。资源关联来自额外API观察并限定于匹配trial，通用祖先关系不推断资源所有权、跨trial对象寿命或取消发起者。辅助函数名属于采集程序，不冒充未知生产入口。未验证完整Chancy工作线程重试/关停行为。报告只指定PostgreSQL18，本地18.7已明确标注。
