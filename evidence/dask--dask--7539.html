Issue findings

Local observation
SQLite returned 3,503 track IDs across four partitions. Dask 2021.02.0 returned zero of them when asked for the index alone. Selecting the track name as well returned all 3,503 IDs. The same index-only read lost all 50 rows in a single-column table. Both affected reads returned every ID on the fixed build.
What CoroPerf showed
Each sampled _read_sql_chunk return on the parent showed a fetched DataFrame with hundreds of IDs and zero ordinary columns alongside a metadata template with zero IDs. The pandas empty property was true for the fetched frame. Dask returned the metadata template. The fixed branch measured the number of rows and returned the fetched frame. Independent SQLite reads reproduced the exact index digest of each recorded chunk.
Scope and limits
The posted call omitted the partition setting required with head_rows=0 and explicit metadata. Running it as written raised the same validation error on all four builds. The partitioned runs supplied this parameter. The catalog is the public Chinook sample database. The CPython stack samples cover synchronous computation. Both synchronous and threaded reads produced the same user-visible results with pandas 1.2.5 and SQLAlchemy 1.3.24.
