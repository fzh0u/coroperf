The report already describes the cause; added evidence identifies the actual operation and historical submission context.
Scope and limits
Read-only diagnostic references retain checked Connections and defer GC: this proves the pool drops an open healthy connection, not durable leakage without the observer. Original min_size3, slow-check sleep0.2s, cancellation at0.1s and existing create_task topology are retained; launch_pool_check only names the existing submission expression. Generic Task ancestry does not infer resource ownership or the cancellation initiator; Pool/Connection identity comes from extra API observations. Exact development source is tested, not cached distribution version metadata. Two exception propagation observations do not prove two exception objects. One successful async component; no replay, sync pool, escaping BaseException, wait_for deadline, starvation, version matrix or fix test.
