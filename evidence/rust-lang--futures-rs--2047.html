Issue findings

Local observation
A ready heartbeat task waits while the first stream poll performs 102 retry attempts on the parent of the fix. With the fix, the heartbeat runs after 31 attempts. One of the fixed poll's 32 child polls parks a retry with an exhausted budget. Both builds eventually complete all 102 attempts. Within each revision, ordinary Rust backtraces show the same RetryBudget::poll and FuturesUnordered::poll_next path for both children, even when their retry budgets and submission order are exchanged.
What CoroPerf showed
The retry samples carry neither a child ID nor a caller label. Their thread and timestamp select the actual child poll interval. The node recorded in that interval then identifies the original push stack. In the displayed run, launch_profile accounts for 96 pre-heartbeat attempts and launch_inventory for six. Records 5–7 and 8–10 bracket the two displayed samples. Withholding the poll intervals leaves the retry stacks unassigned.
Scope and limits
This Linux x86-64 replay uses two bounded, immediately requeued retry futures and a ready heartbeat on LocalPool.
