Issue findings

Local observation
With two async producers and one blocking worker, the median p99 queue wait across two stock-tracing runs per layout was 229.475 ms for the default queue and 1,769.953 ms for the sharded queue. Both routes had the same worker function stack, blocking submit location, and async producer spawn location. Stock tracing distinguished task IDs and recorded their parent IDs.
What CoroPerf showed
CoroPerf attributes each ID-free worker snapshot to the blocking span active on that thread. It follows the blocking task's creation and recorded async producer edge to a launch_profile or launch_inventory frame in the producer's creation stack. All 1,036 snapshots across four captures agreed with independently checked JoinHandle IDs and worker intervals. The displayed sharded examples waited 1,880.170 ms and 1,999.255 ms before execution.
Scope and limits
This is a controlled two-producer extension with 4,400 jobs per run on the reported Tokio revision, using the original tracing interface. The displayed records are the longest sampled wait for each caller in one run. Queue wait is measured from submission to the start of the blocking code.
