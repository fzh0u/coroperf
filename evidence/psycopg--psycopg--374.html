Issue findings

Local observation
The original synchronous session and upstream sync and async tests returned PostgreSQL 25P01 on 3.1.1. A separate insert rolled back before the transaction body ran, leaving zero rows after restart.
What CoroPerf showed
The protocol trace showed no Sync between SELECT and SAVEPOINT. The fix synchronized before BEGIN, and explicitly syncing or fetching the first result also worked.
Scope and limits
The original report omitted server and libpq versions. Task provenance came from the upstream async test and server stacks were captured separately.
