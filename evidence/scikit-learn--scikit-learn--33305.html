Issue findings

Local observation
The reporter requested three coordinates for each of 20 observations. With classical initialization, scikit-learn 1.8.0 returned a 20 × 2 array. Version 1.9.0 returned 20 × 3. Each build also ran with two shared input seeds. Every traced result matched the plain process on every coordinate.
What CoroPerf showed
The outer estimator requested three components on both releases. Segment 2 shows that the 1.8.0 ClassicalMDS initializer received its default of two. Its 20 × 2 result in segment 3 was the array passed to smacof. The low-level solver entered with a request for three components, then took the width of the initializer array, two, in segment 6. MDS returned the resulting two-column array. In 1.9.0 the initializer received three and the solver retained three. On a tetrahedron, the summed squared error in the six pairwise distances fell from 0.075765 to below 1e-16.
Scope and limits
The releases ran on Linux x86-64 CPU with NumPy 2.2.6 and SciPy 1.15.0. The reporter used macOS arm64. The geometry controls use a tetrahedron and 15 observations from the Iris dataset. The table rounds distance error to six decimals. The four physical captures contain synchronous Python calls and zero matched coroutine origins.
