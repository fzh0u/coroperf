Issue findings

Local observation
The four functions in the upstream example returned 42 after a ten-second wait on CPython 3.12.4 and 3.14.3. At entry to f4, the physical stack included f4 and f3. The parent task was waiting in f2. In a second experiment, two consumers awaited each other’s submitted tasks. Both children ran the same code and returned 42.
What CoroPerf showed
coroPerf matched two suspended samples of each child to its creation by task generation and coroutine object. In the original example the creation points to f2, where ensure_future schedules f3. In the crossed experiment, from_west created the child that read_east awaited. The other child had the reverse pairing. CPython 3.14 independently reported each current waiter and its frames.
Scope and limits
The issue requests an async call graph. The crossed-task experiment is a local control. Current waiting relationships came from CPython’s task waiter pointers and, on 3.14, asyncio.capture_call_graph. The coroPerf creation records identify who scheduled each task.
