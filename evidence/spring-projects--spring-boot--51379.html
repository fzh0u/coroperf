Issue findings

Local observation
The reported dump showed one virtual thread waiting for the JAR monitor and another for class initialization, while all four sets of sequential HTTP requests succeeded in the local static-resource app.
What CoroPerf showed
The local virtual thread returned normally through MediaTypeFactory initialization and NestedJarFile.hasEntry. The sole JAR address in the original dump did not identify a lock owner.
Scope and limits
The production app was unavailable and entered through an MVC converter. The static-resource replay does not establish a deadlock.
