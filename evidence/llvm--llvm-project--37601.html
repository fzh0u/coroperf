Issue findings

Local observation
With Clang 6.0.0 at -O2, two instances of the same coroutine resume on one worker and print the same stale pthread ID. The reference call and the Linux TID place both resumes on the worker. Symbolized GDB displays the same functions and PCs for both resumes and omits both launchers. The same-thread and -O0 controls report the current ID.
What CoroPerf showed
In this build, the creation code stores the first pthread_self result at frame offset 0x18, and the resume code reloads it for the diagnostic. CoroPerf uses instruction dataflow on the stripped binary to recover each resume's frame argument from registers and stack bytes. It joins that live frame to its recorded creation stack. Record 2 → 3 identifies launch_inventory, and 1 → 4 identifies launch_profile. Removing either the resume model or creation history leaves both observations unattributed.
Scope and limits
A controlled two-caller extension of the archived Linux x86-64 Coroutines TS reproduction. The app uses frame-pointer omission, and its optimized ELF has application symbols and CFI removed. Numeric test anchors select where to capture. Debug symbols label PCs after the address-based graph is built. Two fresh batches each verify eight joins against the actual resumed handles.
