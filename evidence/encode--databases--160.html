Issue findings

Local observation
The database returned object ID 901 and event ID 101. Reading the result by name returned 101 for the object ID on the report-era client. A positional lookup returned 901. All 412 invoice inserts from the Chinook sample database produced incorrectly mapped records on the proposal parent. Restoring each database recovered every expected object and event.
What CoroPerf showed
The captured backend coroutine compiled the inner event ID first, then appended the four outer RETURNING fields. Record.__init__ received five column descriptions for four driver values. It assigned the outer ID to position one, which held the event ID. Two replays linked the unstarted coroutine returned to Connection.fetch_one to the mapping stack after 4.370 ms and 5.778 ms. The same Record was then used for the incorrect named lookup.
Scope and limits
The historical run used releases available when the issue was filed. A test-only wrapper observed the unstarted coroutine before returning it unchanged to the caller. The contributor proposal passed the submitted test. A control with distinct note and article IDs exposed a remaining column-object lookup error on that branch. The later release comparison changed both databases and SQLAlchemy.
