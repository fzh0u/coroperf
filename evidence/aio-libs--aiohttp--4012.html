Issue findings

Local observation
aiohttp 3.5.4 sent the file in the reporter’s example. The receiver stored it under files%5B%5D, so looking it up under files[] returned an empty list. aiohttp 3.8.0 preserved the brackets and the lookup found the file. When two island data files were uploaded together, both releases delivered both files in the submitted order.
What CoroPerf showed
The encoder’s return value already contained the escaped name. The creation stack in ClientRequest.send identifies the writer task that later sent those exact header bytes. Independent parsing of the saved body and replay through a second server reproduced the field lookup. The file hashes matched across builds.
Scope and limits
The reporter supplied an async client fragment on Python 3.6.8. The local run supplied an upload URL, files and a Werkzeug receiver. Its HTTP 200 receipt exposed what the parser received. The creation and write samples come from the source builds on Python 3.8.20.
