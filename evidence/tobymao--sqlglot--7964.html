Issue findings

Local observation
The reported predicate-pushdown rule moved y.flag = 1 from WHERE into the join condition. Both DuckDB and SQLite then returned one extra row, with flag 0 and a null left key. On 2,000 public flight records, the same rewrite returned every flight for a query that requested the 424 flights delayed by at least 15 minutes.
What CoroPerf showed
In the affected stack, nodes_for_predicate selected the RIGHT JOIN as the target. Its caller put the filter into ON and replaced the outer WHERE condition with TRUE. A right join still emits a right-hand row when the match condition fails, so the flight survived with a null airport column. The fixed rule kept the outer filter, restoring every expected result including duplicate counts.
Scope and limits
This report used the standalone pushdown_predicates rule. The complete optimizer filtered a derived table and preserved the correct result on every tested build. The two database engines agreed across 720 query executions, including inner-join, duplicate-key and null-key controls. These were synchronous SQL transformations.
