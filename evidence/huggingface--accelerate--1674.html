Issue findings

Local observation
With batch size 17 per rank, both four-GPU runs counted 636/10,064 (0.063196) instead of 572/10,000 (0.057200). Evenly divisible batches returned the expected score.
What CoroPerf showed
The caller reduced each rank to scalars before gather_for_metrics trimmed the final batch, so it kept all four subtotals, including 64 duplicate IDs that were all hits.
Scope and limits
This matches the maintainer’s explanation of API usage. The replay used Ubuntu 22.04 instead of 20.04. The unpadded control was stopped while ranks waited.
