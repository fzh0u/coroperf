Issue findings

Local observation
The report's JSON asks for the last message on subject6077 before a time that predates every stored record. All 6 replays on the fix parent returned sequence 10, “Message 10”, followed by 204 EOB. All 6 replays on the fix returned a single 404 No Results frame. The verifier checked 144 checksummed records across 12 file-store replicas against 48 acknowledged writes and 48 sequence reads.
What CoroPerf showed
The parent mapped the cutoff to sequence 1, subtracted one, then treated zero as an unspecified ceiling and substituted the current tail, sequence 10. The fix checked the lookup against the first stored sequence before subtracting. The reply inbox identifies the handling goroutine on parent member n2 (Go ID 131) and fixed member n1 (Go ID 288). Each retained runtime trace links that instance's creation and exit to its stack in getDirectMulti.
Scope and limits
The literal JSON comes from the issue. The binaries are built from the exact fix parent and fix. The reporter named a development build, and the separate Java follow-up was not executed. The upstream Go regression runs separately on a single file-store server. Three client endpoints, checksummed replica files, nanosecond boundary queries and the second subject are local controls. The captured goroutines serve multiple requests. This discrepancy concerns selection from replicated data.
