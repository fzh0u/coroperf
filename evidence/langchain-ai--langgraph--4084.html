Issue findings

Local observation
The reporter's async task returns the literal string “Task 2”. The entrypoint awaits the task, prints what it received, and returns that value. Under ainvoke and astream it printed “Got: (Task 2)” on every build. Under astream_events the 0.3.21 and 0.4.6 wheels printed “Got: (None)”. The child end event still contained “Task 2”. The entrypoint and graph end events both contained None. The same discrepancy was present on both sides of the PR that closed the issue and on the 1.2.18 wheel. The parent of the later fix reproduced it. The merged fix, the 1.2.19 wheel and the November 19 1.2.23 wheel all delivered “Task 2” to the caller.
What CoroPerf showed
In the 0.3.21 capture, CPython recorded the allocation of the child task's arun_with_retry coroutine in submit at langgraph/pregel/executor.py:155 (segment 67). It observed the new object before its first await. The same retained frame was running at langgraph/pregel/retry.py:126 (segment 101). Its writes already contained (__return__, “Task 2”). The streaming branch had drained the child output and then returned None. The result-copy callback delivered that value to the waiting Future (segment 103), and the reporter's local task_value was None (segment 105). On the merged #9407 build the retry coroutine read the written value and returned “Task 2” (segment 84 of the comparison graph). The fix's regression task returned 42 and 0 under both event protocol versions, with and without an attempt timeout. The merge parent returned None for both values.
Scope and limits
The reporter listed langchain-core 0.3.49 and omitted the LangGraph version. The reconstruction pairs that core release with the 0.3.21 wheel. The graph runs locally with a Python function and uses no model service. The #4805 async test checked stream outputs from a workflow that returned the literal “done”. Its stream assertion failed on the parent, and the merged version passed its event snapshot. That workflow discarded the values returned by its child awaits. The separate token-batch workload compares the child event with the object delivered to its caller. On affected builds the ordinary counts reached the child end event. The caller received None and raised TypeError when it indexed that value. On the fixed builds it received the dictionary and computed 3.0 or 5.0 tokens per sequence. The original literal-string program completed normally.
