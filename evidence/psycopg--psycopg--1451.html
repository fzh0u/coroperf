Issue findings

Local observation
One real transaction-entry cancellation at affected client checkout99356800 leaves the reused Connection at transaction depth1/INTRANS. A later transaction context exits normally, but the same Connection sees1 inserted row and an independent Connection sees0. Explicit rollback raises ProgrammingError. The successful process exits0 and connections/table/private PostgreSQL are cleaned up. Later-batch startup through success takes28.79s; one preceding observer failure in that batch occurred before cancellation.
What CoroPerf showed
Generic CoroPerf Task creation plus a file-scoped cancellation exception observation restores launch_interrupted_entry. An API-boundary observation after the later transaction exits restores launch_reuse_check. Both helpers are absent from current observation stacks and present in the causal stacks. An explicit Connection/Task observer independently binds the cancelled-entry Task, later reuse Task and rollback failure to the same actual Connection, showing depth1/INTRANS across phases. The two selected joins are3→5 and29→31. A later cleanup Task reuses the reuse Task address, but its distinct runtime generation prevents joining their records.
Scope and limits
This tests exact checkout99356800e90aa0e7b604f652d714ef0f33422b47 using cached CPython3.14.3/PostgreSQL17.1/pure-Python libpq, whereas the report used3.14.8/18.4. The checkout reads version3.3.9 from installed distribution metadata; this is not a released3.3.9 behavior claim. Connection and context-manager wrapper identities require the explicit API observer; generic Task ancestry does not infer shared resources or hidden AsyncTransaction identity. Submission helpers are introduced for this standalone harness. The source already describes stack cleanup; the added diagnostic facts are historical callers and observed cross-phase resource state. Two earlier observer failures are retained, one in b14 and one in b15; neither reached cancellation. No successful scenario replay, nested-savepoint test, alternate server/implementation/version or fix run.
