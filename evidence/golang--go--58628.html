Issue findings

Local observation
One Go 1.23.0 check uses the original two io.Pipe objects and io.Copy. Closing the destination writer does not return the copy within an 80ms observation. Goroutine 161 remains in pipe read; its native dump shows the immediate startCopy creator but omits submitConsoleMirror. Closing the owned source during normal cleanup ends this same run, with process exit 0.
What CoroPerf showed
Standard runtime trace records the real goroutine birth with its full creator stack, a pipe-read waiting transition, and eventual exit. The native child-reported ID and independent all-goroutine snapshot both match trace goroutine 161. CoroPerf joins the creation to the blocked stack and exposes submitConsoleMirror. The measured native waiting interval is about 80.82ms. The source information already exists in runtime trace; CoroPerf supplies the normalized identity join and combined view.
Scope and limits
This is the upstream in-memory pipe example with named submission helpers and one bounded observation. It does not prove infinite lifetime, socket or descriptor retention, Docker integration, or a runtime defect. Only one transfer ran. Source cleanup is part of ending that same run; no alternative implementation, repeated transfer, version matrix or fix validation ran.
