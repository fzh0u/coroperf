Issue findings

Local observation
In the checked Ray streaming branch, the second prompt starts after the first finishes. With the open proposal both prompts start before the first finishes, and the faster prompt can deliver the first chunk. For one two-prompt batch the CPU fixture takes a median 115 ms on stock and 77 ms on the proposal. The prompt indices, text deltas and finish reasons are preserved.
What CoroPerf showed
Producer enqueue stacks have identical frames. The exact active Task, coroutine and coroutine frame link the selected enqueue records 6 and 7 to producer creations 3 and 4. Following the creating Task connects them to separate request creations 0 and 1. The actual queued tuple links each producer to the request that emits its SSE chunk, even when the two requests use the same prompts in reverse order.
Scope and limits
This runs the real Ray streaming methods and SSE formatting with deterministic asynchronous engine responses on CPU. The timings quantify the reproduced serialization and overlap in this fixture. Two runs verify eight producer-to-request joins and sixteen delivered queue objects. The checked master revision still has the serial branch. The issue and PR remain open.
