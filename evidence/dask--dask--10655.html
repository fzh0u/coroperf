Issue findings

Local observation
The reporter supplied two January rows. Dask 2023.10.1 returned an empty tuple for month end when the second date was January 31. Changing only that date to January 30 returned the January 31 count of 2. Month start returned 2 in both cases. The full January and quarter inputs also lost their expected end-labeled counts of 31 and 90.
What CoroPerf showed
The planner retained one output boundary when the final input date equaled the period label. Forming intervals from adjacent output boundaries produced zero aggregation keys. The finalizer received zero partitions and returned an empty tuple. With January 30 as the last input, the planner produced two boundaries and a thread-pool worker counted both rows. Independent calendar counts and pandas agree across the measured inputs.
Scope and limits
The original examples use one partition. The local run used Linux and the reported Python, Dask and pandas versions. The taxi input consists of December 2024 pickups before 00:05 each day, grouped by pickup date. The release comparison uses each version’s default execution path. Dask 2025.12.0 with pandas 2.2.3 raised IndexError on the January 31 input. The issue was open when checked. The capture records local Python stacks and supplies no coroutine creation identity.
