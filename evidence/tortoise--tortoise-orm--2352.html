Issue findings

Local observation
On the reported revision, fix parent and 1.1.9, CASE failed on a missing e__t.name and filtered COUNT returned zero for one matching child. Both queries returned one on the fix commit.
What CoroPerf showed
The old COUNT queried only the parent table, and this SQLite build treated the unknown quoted column “n” as text. Propagating the join produced a LEFT OUTER JOIN and counted the child.
Scope and limits
SQLite only, using the report’s two rows. The verified Task origin belongs to a separate related-object prefetch.
