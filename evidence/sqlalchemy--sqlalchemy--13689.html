Issue findings

Local observation
Two async writers run the same SQL. Both writers have been collected by the time two separate Tasks read their cached results. In 2.1.5 both reads raise the same TypeError with the same traceback. The coroutine origin and tracemalloc identify the common fetchall allocation inside FrozenResult. The reader Task creation traceback reaches the shared dispatcher.
What CoroPerf showed
The same FrozenResult and its contents are observed at the original write and the later read. The exact result object connects each reader's creation stack to the earlier writer's creation stack. The displayed joins 1 → 17 → 20 and 2 → 18 → 22 identify start_import and start_refresh respectively. In the mainline fix both read Tasks return the same two rows successfully.
Scope and limits
This replay extends the Core streaming result example with two writers and two readers. It uses CPython 3.12.3 and SQLite, SQLAlchemy 2.1.5, and the recorded mainline fix with version 2.1.6. Two batches verify 32 cache handoffs, including 16 failures and 16 successful reads. Removing the result-object edges leaves just the shared reader dispatch and its execution stack.
