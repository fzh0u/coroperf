Issue findings

Local observation
When MongoDB returned zero users, Express 4 with explicit next(err) and Express 5 with native forwarding both returned HTTP 200 with JSON code 404, while an unmatched route returned HTTP 404.
What CoroPerf showed
The same Mongoose Query and route Promise linked the empty lookup to middleware, and Express 5 recorded the router’s then continuation.
Scope and limits
The tested error came from the detail controller. The original unhandled rejection, stalled connection and process exit were not reproduced.
