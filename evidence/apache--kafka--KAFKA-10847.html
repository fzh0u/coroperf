Issue findings

Local observation
With a 100 ms join window, the legacy API in 2.6.1 and 3.1.0 emitted both unpaid and paid for order A when payment followed by 5 ms, but only paid when payment arrived first.
What CoroPerf showed
On the same 3.1.0 build, the new window API buffered A until its payment arrived. It emitted the genuinely unpaid order B only when a later record advanced event time, preserving B’s original timestamp.
Scope and limits
The upstream change introduced new semantics and retained the legacy API. Tested a single-partition left join with zero grace.
