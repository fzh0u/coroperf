Issue findings

Local observation
The reported revision and pinned main use the same two-part metadata loop. For 32 chunks with two metadata fields first appearing in the final quarter, median thread CPU per coalescing call falls from 17.0–17.8 µs to 9.18–9.81 µs with the local patch. For 32 chunks with all five standard fields present throughout, it falls from 22.4–23.2 µs to 15.2–16.4 µs. All 20 measured input shapes preserve the output and metadata key order.
What CoroPerf showed
Two coalescing calls have identical execution stacks. The live Task, notification Event and drained output list join records 2 and 3 to the interactive and batch launches in records 0 and 1. The batch launch owns the 32 queued chunks and their per-token annotations. The interactive launch owns two chunks with no incremental metadata fields. Swapping the backlog and launch order moves the coalescing work to the interactive request, whose execution stack has the same frames.
Scope and limits
This isolates the streaming backlog item from the original report. The trace uses pinned SGLang frontend methods and prepared detokenizer packets, with the bursts delivered in one event-loop turn. Separate thread-CPU timings use 7 trials per hash seed and 3,000 calls per trial. GPU inference, HTTP transport and client latency are outside the replay. GitHub closed the issue for inactivity. The coalescer remains unchanged at the inspected main commit, and the comparison uses a local patch.
