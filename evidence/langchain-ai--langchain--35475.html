Issue findings

Local observation
The posted program copied the second item’s result to the third in three runs, and local sync and async classifiers marked a twice-failed HTTP 503 input successful with another input’s classification.
What CoroPerf showed
The retry saved the success for index 1 correctly, then filled index 2 by popping that same value from the last round and delivered it through the original run ID’s success callback.
Scope and limits
The original assertion was synchronous. Task origins came from abatch, and two proposed changes were tested separately on the reported version.
