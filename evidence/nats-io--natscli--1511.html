Issue findings

Local observation
Running nats str cp old new printed “Stream old was created” with NATS CLI 0.3.0. The server had created new. Its two mirrored messages could be read through all three endpoints, and the original stream retained its creation time. A regular stream copied from Input to Output showed the same naming error.
What CoroPerf showed
The Go stack stopped at cpAction with the server result naming new. The subsequent Printf call received old as its formatting argument. On the fixed commit it received new, which matched the cluster state. Reading the argument at both call sites locates the discrepancy in the CLI output.
Scope and limits
The original issue omits the source stream configuration. The exact command was run on a mirror, with a separate ordinary-stream control using distinct subjects. The detail heading below the corrected success message continued to show the old name. These stacks come from the synchronous CLI path.
