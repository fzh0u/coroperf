Issue findings

Local observation
In all five old-SDK runs, the workflow waited on its second Promise, the service history recorded only the first local activity, and the workflow eventually timed out.
What CoroPerf showed
The handler reported one pending activity, none outstanding and no follow-up task. Applying only the #1295 handler patch to 1.13.0 reversed those counts, requested another task and completed all five runs.
Scope and limits
The upstream JUnit case used the official test service’s virtual clock. Run IDs linked stacks and histories. The CLI did not automatically flag the long wait.
