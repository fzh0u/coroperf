Issue findings

Local observation
In 4.1.5, a null non-frozen list passed l < [1,2] and became [9], while a frozen null list failed the condition. An update guarded by l >= [] also applied where 4.1.6 rejected it and preserved [3].
What CoroPerf showed
In 4.1.6, valueAppliesTo returns false for an empty storage iterator. Replacing just the collection-condition class on a 4.1.5 node reproduced that decision.
Scope and limits
Three healthy loopback nodes exercised Paxos v2. The reported DELETE condition behaved differently locally, and no cross-node stack edges were inferred.
