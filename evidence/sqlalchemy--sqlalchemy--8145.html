Issue findings

Local observation
On SQLAlchemy 1.4.37, cancelling the original async exit path left a real PostgreSQL connection checked out.
What CoroPerf showed
Pool checkout and return records placed cancellation between __aexit__ and close and provided a comparison with the shielded fix. The same Task created by main borrowed the connection and received cancellation during close. The pool recording identifies its checked-out connection.
Scope and limits
The only change to the original workload was the private PostgreSQL address.
