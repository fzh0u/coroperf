Issue findings

Local observation
Three delayed REST inserts pinned a Quarkus virtual thread with the pooled-lo optimizer, and the paired none controls recorded no pins. Every request returned 201 and a separate SQL query confirmed the row. PostgreSQL reported a nextval relation-lock wait in all six runs.
What CoroPerf showed
The selected probe wrapped Quarkus's existing factory, recording the child JDK thread ID before start and the real request dispatch stack. The same thread ID owned the JFR pin sample through PooledLoOptimizer.generate and the JDBC read. Retaining the original factory preserved the virtual-thread name. Disabling the optimizer removed the pin.
Scope and limits
This restores the creation stack for the Quarkus example published after the specific Hibernate report. The reporter's production deployment was unavailable. The optimizer comparison holds the same driver, JVM and database constant.
