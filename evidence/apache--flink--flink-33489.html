Issue findings

Local observation
All four groups in the reported query contained commas where the query requested #. The Chinook catalog returned the correct genres for every invoice. All 166 invoices with multiple genres used the wrong separator. The other 246 invoices had one genre each. Both independent batches produced the same affected invoice IDs.
What CoroPerf showed
At SplitAggregateRule.matches, the debugger recorded the planner accepting a DISTINCT LISTAGG call with two operands. The physical plan still contained # in the partial aggregate. Its final aggregate received only the partial string. Flink then constructed the one-argument aggregate, and its streaming task used the default comma. Replacing just the upstream planning method made the same call return false and restored # in every affected group. Disabling splitting independently produced the same result.
Scope and limits
The local jobs used Flink 1.18.0. The rule comparison transplanted the corrected method from 1.19.0 into that release. SQL leaves member order unspecified, so verification compared the members and delimiters separately. The Java debugger captured physical planning and worker stacks. A per-coroutine creation site remains unverified.
