Issue findings

Local observation
The same search returned neighbors a and b on every path. In redis-py 4.5.1 and the parent of the fix, direct search returned a Result with two documents. Both pipelines returned a raw array. All 99 ordinary pipelined reads in the reporter’s program returned their expected values.
What CoroPerf showed
The captured FT.SEARCH replies contained identical IDs and distances on all three paths within each run. The parent transaction stacks showed that neither pipeline had a response callback for FT.SEARCH. The fixing commit registered the callback on the search module’s pipeline and that instance entered the document parser. The generic pipeline still returned an array. On 8.1.0 the search module pipeline produced Result objects with unified responses enabled for either tested protocol.
Scope and limits
The reporter gave no client or server version. We chose 4.5.1 from the month before the report and ran all clients against Redis Stack 7.2.0-v18. The original script used a synchronous client and an HNSW index. A separate FLAT index checked 120 searches over 150 Iris records against independently calculated distances.
