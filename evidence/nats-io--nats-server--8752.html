Issue findings

Local observation
An operator queried a three-server JetStream cluster with known client connections. On the first server, three of four clients matched Bob. The first page returned one Bob row and reported four matches. A query with zero matches also reported four. The fixed server returned totals of three and zero. All 36 message readbacks across the four runs succeeded.
What CoroPerf showed
The Go runtime trace follows the listener spawning the connection goroutine through the filtered count and the HTTP reply. For Bob’s first page, the count sample saw four open clients, three matches and a response total of four. The fix assigns the match count before paging the result. The client port and response pointer identify the request that received the sampled total.
Scope and limits
The reproducer uses new HTTP connections on healthy local clusters. Both revisions ran with stock binaries and with observations on one server. The scope is the monitoring response’s total field.
