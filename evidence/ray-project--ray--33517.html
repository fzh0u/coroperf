Issue findings

Local observation
The original Ray 2.3.0 driver created 100 one-row blocks and mapped them in batches of ten. It printed all integers from 100 through 199. The final terminal line still read 10/100. The same result appeared with and without the stack observer.
What CoroPerf showed
The bulk executor initialized the bar from the estimated output count of 100. It advanced the bar once per output bundle and emitted ten bundles. Samples at initialization, the last increment and the underlying display’s close operation identify the same bar. With the upstream change, the final display used the completed bundle count. The seven-row control showed 15/15, and one row per batch showed 100/100 on both builds.
Scope and limits
Ray 2.6.0 rejects the original Python list blocks. The cross-version control carries the same indices in Arrow tables and compares every returned value. The isolated commit comparison loads the two Python modules changed by the fix on the 2.6.0 runtime. The measured stack belongs to the synchronous driver.
