Issue findings

Local observation
The reporter added hello=world to an HTTPS GET whose URL already contained the bare field foobar. HTTPX 0.23.0 and the immediate parent of the fix sent /get?hello=world. The fixed commit and HTTPX 0.23.1 sent /get?foobar=&hello=world. The loopback server returned HTTP 200 for all 64 HTTPX requests and the independent reference request. On two fresh SeaweedFS stores, losing the uploads selector changed the list itself. The affected release returned one completed object, parts/complete. The fixed release returned the two pending uploads, parts/pending-a and parts/pending-b.
What CoroPerf showed
The affected parser received the string foobar and returned an empty dictionary. The merge consequently received an empty base and retained only the added field. The fix sets keep_blank_values=True at the parser call. The parser then returned one empty-string value under foobar. The same QueryParams object entered the merge, and the resulting request target matched the h11 writer and the server request line. In two additional batches, the GET_AWAITABLE instruction in the reporter’s main function exposed the newly created AsyncClient.get coroutine on line 6. Its cr_origin pointed to that line. The same pinned coroutine frame was present on the physical parser and writer stacks while it was running.
Scope and limits
The reporter program changes only its destination authority for loopback HTTPS. The additional query shapes and no-merge runs are local controls. The fixed release emits an equals sign and places foobar first. The reporter’s literal spelling was checked with a separate stdlib request. Each plain/profile pair yielded identical HTTP bytes. The 32 detailed parser/merge graphs contain 256 synchronous frame samples. The separate lifecycle check measured eight real get coroutines and eight plain GETs across four builds. Its three segments cover creation, parsing and writing. Closure was read after execution. The separate SeaweedFS 3.93 control used local HTTP and matched the returned upload IDs to successful initiation responses from each store.
