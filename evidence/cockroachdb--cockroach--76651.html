Issue findings

Local observation
With the reporter’s six SQL statements, the v22.1.0 client escaped the six UTF-8 bytes for the Chinese greeting “hello” in CHAR(10) but displayed the two characters correctly in VARCHAR(10).
What CoroPerf showed
Type comparisons, encoder arguments and return values isolated the old CLI formatter’s byte branch, while the linked fix switched the CLI driver to pgx.
Scope and limits
The report omitted the version. Independent libpq reads and GDB checked padding that the table display trims.
