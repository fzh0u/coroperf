Issue findings

Local observation
The median time to route the slower of two ready first-audio replies is 89.89 ms with four additional idle replicas after PR #4527. On that tree, a nonblocking poll with a one-item limit takes 0.55 ms and the historical 16-item draft port takes 0.44 ms. Current mainline takes 1.26 ms with its default event-driven readers and 90.55 ms with its legacy loop explicitly selected. Each configuration runs seven CPU trials. The two PCM chunks match in every trial.
What CoroPerf showed
Two first-audio reads have identical engine frames. Matching the live reader Tasks connects them to their respective replica sources through 9 → 3 → 2 and 10 → 4 → 2. Each original audio object survives processing; the exact OutputMessage reaches the Task waiting for its request. The frontend observations then join 11 → 0 for the interactive launch and 12 → 1 for the batch launch. Reversing the workload assignments swaps the replica associations while preserving output identity.
Scope and limits
The fixture runs the pinned orchestrator loops, queue reads, stage-pool output path, and message routing. The CPU fixture supplies model-stage output and gives each replica a real asyncio queue. The measurements cover enqueue to frontend delivery for these already-produced chunks. GPU audio generation and deployment-wide TTFP are outside this comparison. Issue #4561 is open. Merged PR #8675 makes the verified event-driven path the default.
