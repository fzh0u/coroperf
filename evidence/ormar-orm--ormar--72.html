Issue findings

Local observation
The posted query asks for five parent models with their keywords. In 0.7.5 the five database rows belong to parents 1, 1, 2, 2 and 2. ormar returned two parents. The fixed query fetched eight joined rows and returned five parents with their keywords. The original pytest suite passed all 21 cases on 0.8.0. In a second dataset of seven Chinook playlists, the old second page still contained TV Shows from the first page. The fixed second page contained three classical playlists.
What CoroPerf showed
At the await expression in the posted test, CPython exposed the unstarted QuerySet.all coroutine and its creation frame. The same coroutine was running when LimitQuery.apply added a limit to an expression that already contained both joins. SQLite executed that statement, and the recorded input to merge_instances_list contained only two distinct parent IDs. The fixing commit called LimitQuery.apply inside a parent-only subquery and then joined its rows. The new opt-in raw-row limit reproduced the former first-page behavior.
Scope and limits
The reporter did not specify a version or provide the database bootstrap module. We supplied a private SQLite database and tested the release available on the reporting date as well as 0.7.5. On 0.7.3 the single-loop harness also encountered relation bookkeeping and child hydration differences. The primary capture uses 0.7.5. The playlist dataset retains all memberships in the seven selected playlists, with the title field widened to fit the original track names.
