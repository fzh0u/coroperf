Issue findings

Local observation
The v3 member add command registered the fourth member but printed only its ID and the cluster ID. API v2 printed three join variables. With the fix, the v3 text output also included ETCD_NAME, ETCD_INITIAL_CLUSTER and ETCD_INITIAL_CLUSTER_STATE. All four members subsequently served quorum reads.
What CoroPerf showed
At registration the server knew the new member’s ID and peer address. Its name remained empty until the process joined. The corrected CLI matched the ID in the response to the CLI argument newMember and printed a complete peer list. After startup, the four membership views confirmed that name and address.
Scope and limits
The original report compared v2 and v3 without specifying an exact topology or version. The replay used the command from the merged documentation with three initial voters and a fourth process started from independently prepared configuration. Eight cluster runs covered both client revisions, text and JSON output, and GDB observation. The observed stacks belong to the synchronous CLI.
