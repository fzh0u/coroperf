Issue findings

Local observation
Cassandra 3.11.2 returned null in two of the four JSON rows from the reported queries. One held an empty text column. The other had an empty clustering key and age 42. Ordinary SELECT returned zero bytes for both text values. Apache releases 3.0.8 and 3.11.3 rendered both as the JSON string "".
What CoroPerf showed
The parent renderer received a present buffer with zero remaining bytes and appended the four characters null. The fix appended two double quotes. The observed return bytes matched the native protocol response for each row. After a flush and clean restart, the same reads reproduced the discrepancy. Offline SSTable export recovered the empty values in all seven databases.
Scope and limits
Each build ran on one healthy node. The client replayed the successful CQL from the report over native protocol v4. Omitted-column and absent-partition reads, direct clustering-key lookup, and the persistence checks are supplemental. The exact parent and fix runs compiled their Selection.java against the same 3.11.2 distribution. The physical stacks identify native request workers. Coroutine creation was unobserved.
