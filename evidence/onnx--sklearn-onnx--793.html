Issue findings

Local observation
On the four rows from the landed regression test, the skl2onnx 1.20.0 wheel and the immediate fix parent each produced six wrong float32 values in ONNX Runtime (ORT) CPU. For [-1, -2, -4], ORT returned [1, 2, 4]. Scikit-learn and independent division by the row’s largest absolute value gave [-0.25, -0.5, -1]. The zero row and the positive-dominant row matched on every build. L1 matched scikit-learn exactly, and the largest L2 difference was 5.96 × 10⁻⁸. The source fix reproduced all 12 expected max-normalized values.
What CoroPerf showed
The converter stack shows apply_normalizer selecting ai.onnx.ml.Normalizer(MAX) and add_node inserting it into the serialized model. ORT’s CPU profile records that operator executing. Its output fits division by the signed maximum. In the separate seven-row pipeline, ORT CPU and ONNX ReferenceEvaluator loaded the same bytes for each build. For the parent model, the converter and both executors recorded SHA-256 a6c929a45f8e85fc1844ab7c3acb8e1de513bb2dc743af51027ac3b83203d4fa. On both older models, ReferenceEvaluator’s _run called norm_max. Its recorded row divisors were [4, 4, 4, 4, 0, 8, 8], and all seven outputs matched scikit-learn. For [-4, -2, -1], ORT returned [4, 2, 1] and ReferenceEvaluator returned [-1, -0.5, -0.25]. The fixed converter emitted Abs, ReduceMax, Div, Less and Where. Both engines matched all seven rows, and ReferenceEvaluator bypassed norm_max.
Scope and limits
The reporter described a sign discrepancy and later identified a one-step scikit-learn Pipeline. Neither post provided the numeric input or exact versions. The first table uses the four-row fixture from PR #1271. The second uses a separate seven-row pipeline inspired by the comment. These runs used float32, opset 18, scikit-learn 1.8.0, ORT CPU 1.24.4 and ONNX ReferenceEvaluator 1.20.1. The parent and fix were measured from source. The sealed release index listed 1.20.0 as the latest wheel. Converter stacks establish which nodes were emitted. The ORT trace covers Python dispatch, CPU kernel events and returned tensors. Its internal divisor is inferred from the numeric outputs. The reference executor exposed its divisor directly. All captured stacks were synchronous.
