Issue findings

Local observation
Assigning device 7 to missing user 102 reproduced the foreign-key error and 21 consecutive framework and runtime frames, but the stack showed only the transaction entry and omitted Device.update.
What CoroPerf showed
MySQL reported 1452/23000 on UPDATE before rollback; adding user 102 allowed commit and readback, while separate promise and error-identity checks distinguished two otherwise identical caller stacks.
Scope and limits
The private SQL, route and dependency lock were unavailable. The maintainer’s suggested failure at COMMIT did not occur in this transaction.
