Issue findings

Local observation
The reporter’s full-object query included the author join. On 0.25.1, 1.1.9 and the proposal parent, selecting just the book ID removed that join but kept the author column in ORDER BY. PostgreSQL returned SQLSTATE 42P01. SQLite reported a missing column when the same calculation used a portable CAST.
What CoroPerf showed
The recorded values() call began with author in the requested relations. Its returned ValuesQuery had an empty relation list, and _make_query built zero joins. The submitted patch carried the relation into the projection, producing one join. PostgreSQL and SQLite then returned the same six ordered catalog IDs for dictionary and flat projections.
Scope and limits
The posted module printed SQL. The launcher supplied the omitted RawSQL import and called the published main(). The database runs added six GITenberg catalog entries and used the difference between death year and birth year as the integer sort input. The proposed fix was open at collection time. The recorded stacks cover query construction and database execution.
