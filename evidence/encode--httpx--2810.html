Issue findings

Local observation
For GET /path?query, the upstream echo application returned {"raw_path": "/path?query"} on both the HTTPX revision cited in the report and the parent of the fix. The fixed revision and the direct Uvicorn control returned {"raw_path": "/path"}. All 72 loopback exchanges returned HTTP 200. The 16 incorrect bodies came from query-bearing requests relayed through affected HTTPX code. Each build returned identical response bytes with and without instrumentation.
What CoroPerf showed
The client kept the query in URL.raw_path. The affected ASGI transport copied those bytes into the application scope, which already exposed the query separately as query_string. The fix splits the request target at its first literal question mark. The encoded question mark (%3F) therefore stays in the path. In the parent relay capture, segment 10 records Uvicorn creating a request Task, segment 14 observes that same Task in the upstream echo function with HTTPX on its stack, and segment 18 records its normal exit.
Scope and limits
The reporter identified a difference between HTTPX and Uvicorn. The concrete request and echo function come from the upstream fix’s regression test. That test calls the application in process. The TCP relay, additional targets and Task identity evidence come from the local controls. The tables cover the single batch identified as the primary run.
