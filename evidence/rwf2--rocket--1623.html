Issue findings

Local observation
On the reported nightly and mold version, two runs with standard zlib-compressed SQLx debug sections produced “Error: foo” with 21 of 22 frames unknown. Lld and the fixed linker left only one unknown.
What CoroPerf showed
One sqlx_rt object had outer alignment 8 but declared alignment 1. The old linker inserted two extra bytes before DWARF unit 119, and the runtime resolved the same application address only after the fix.
Scope and limits
The source and lockfile were public, but the original linker-input archive returned HTTP 410. The compressed input was rebuilt locally with a different OS and LLD version.
