Issue findings

Local observation
For input [1, 1], the original forest returned two distributions that each summed to one. After export, ONNX Runtime returned probability sums of 2.50 and 2.56. The top labels for this input still agreed. Across all nine possible inputs, three had a different predicted label. On 360 held-out digit images, 39 images had at least one label different from the reference forest.
What CoroPerf showed
The conversion stack identifies the multi-output forest’s leaf-vote calculation. For the first tree, both outputs had leaf counts [3, 3, 0]. The exported graph turned each nonzero count into one, giving [1, 1, 0]. The fix divided by the total count to produce [0.5, 0.5, 0]. Executing the saved models and independently recomputing the tree votes confirmed this difference.
Scope and limits
The reporter’s model uses 100 trees and two categorical outputs. The additional digit workload derives parity and a threshold label from each digit. Label disagreement is measured against the reference forest’s prediction. CPU inference used ONNX Runtime 1.9.0, and the comparison allowed an absolute probability difference of 0.000001. Both conversion and inference were synchronous.
