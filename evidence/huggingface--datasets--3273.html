Issue findings

Local observation
In the reporter’s example, Datasets 1.15.1 returned the second column in the order [3, 1, 2]. Two independently sorted views of the English Web Treebank produced 2,077 mismatched sentence and annotation IDs, one for every sentence checked. Datasets 1.16.0 returned [1, 2, 3] for the example and matched every sentence to its original tag sequence.
What CoroPerf showed
The stack records concatenate_datasets building a single six-entry index for two three-row inputs. Reading the first three rows then applies the left input’s order to both columns. The fixed build calls flatten_indices on each input to put it in its own logical order before joining columns. Explicitly materializing both inputs also restores the correct pairs on the older release.
Scope and limits
The issue gives no exact version. The comparison covers the 1.15.1 and 1.16.0 wheels, the issue-day revision and both sides of the fix. The treebank follow-up checked the first 2,077 rows against an independent SQLite join on sentence ID. All captured functions ran synchronously.
