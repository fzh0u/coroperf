Issue findings

Local observation
A request for bytes 500 onward in a 10,000-byte file returned HTTP 206 and the correct 9,500 bytes on aiohttp 3.0.9. The Content-Range header was missing. curl and Wget each left the original 500-byte file in place. After the fix, both produced the complete 10,000-byte file with the expected digest.
What CoroPerf showed
The creation and execution records identify the same request task in FileResponse.prepare(). In the affected source-parent capture, 679.371 µs elapsed from the recorded create_task return to the stack immediately before sendfile. The archived recorder uses the same monotonic clock and thread for both records. The range calculation and payload length agreed with the actual response bytes. In a separate replay, adding Content-Range alone let both clients finish. Adding only Accept-Ranges left both downloads incomplete.
Scope and limits
The experiment used the reported aiohttp version and the framework’s real static route on loopback. The tested download clients were curl and Wget. The browser download behavior comes from the upstream report.
