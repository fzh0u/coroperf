Issue findings

Local observation
Both streaming routes detokenize on the event-loop thread on the affected revision. The merged repair moves that work to the renderer executor. In the separate CPU renderer CLI runs, concurrent tokenize requests had a p95 of 155 ms on stock 0.28.0 and 57 ms with the fix. Aggregate streaming throughput went from 1,993 to 1,753 tokens/s. Both runs returned the expected text.
What CoroPerf showed
On the fixed revision, chat and completion detokenization have identical physical worker stacks. The executing threads hold the exact WorkItem objects recorded in executor submission. CoroPerf joins records 5 and 8 to submissions 4 and 6, which restore the two route-specific coroutines. The submission records link to the respective stream Task creation in records 0 and 1. The same check attributes all 16 observed chunk calls to the two routes.
Scope and limits
The joined sample uses the actual FastAPI routes and a local tokenizer through in-process ASGI on CPU. It verifies route attribution, thread placement and decoded text. The performance figures come from separate uninstrumented TCP runs with 20 streams and a closed-loop tokenize client, with one run per version. PR #57528 merged and closed the issue.
