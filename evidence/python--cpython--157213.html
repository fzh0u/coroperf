Issue findings

Local observation
On CPython 3.14.3, the stock call graph still lists the gather waiter after a sibling has failed and the waiter has moved on. The upstream patch removes that stale edge and retains a later direct waiter where one exists. Once the callback Handles are collected, the inspected Task stacks, debug creation tracebacks, coroutine origins, and built-in call graphs omit both original launchers.
What CoroPerf showed
CoroPerf connects each pending survivor snapshot to the creation of the same Task. The Handle that was running when dispatch created that Task connects its creation to the earlier call_soon stack, which identifies launch_profile or launch_inventory. The callback edge is necessary to distinguish the two creators in these captures.
Scope and limits
The upstream issue concerns current await edges. Caller attribution is evaluated in a controlled two-launcher extension on Linux with a scoped callback probe. The two traces below use CPython 3.14.3 with the official backport applied to a private copy of asyncio/tasks.py.
