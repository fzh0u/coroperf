Issue findings

Local observation
Version 1.1.1 printed six rows for the input’s two records, including a new row for “nuff: 1”. Versions 1.2.0 and 1.2.1 printed two complete records. All three batches produced identical stdout with the recorder enabled and disabled on each build.
What CoroPerf showed
The creation stack and the _read_until sample identify the task that cut the first quoted field. The same reader passed a buffer ending at that newline to the standard-library parser. The truncated dictionary returned by the reader is the same object the reporter’s print call received.
Scope and limits
The report gave no version pins. The local measurements run from task creation through the first malformed dictionary at print. The fixed capture observes the compiled parser’s returned fields.
