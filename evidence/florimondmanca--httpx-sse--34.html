Issue findings

Local observation
A successful HTTP response carried one SSE event with U+2028 inside its JSON string. Version 0.4.1 delivered a string ending at Hello. Chromium EventSource, the fixing commit and release 0.4.2 delivered the complete JSON document.
What CoroPerf showed
The client gave SSEDecoder.decode two lines for a single data field. The suffix beginning with World was ignored and the next blank line dispatched the truncated event. The repaired line splitter kept U+2028 within that field. The task created in main was the one that ran decode and received the returned event object.
Scope and limits
The original example uses a synchronous in-memory stream. The task-origin evidence comes from a local async HTTP client reading the exact same response bytes over loopback. Chromium closed after receiving the first event. The Python client read to the end of the stream.
