Issue findings

Local observation
The reporter used await client.list(path) on an anonymous FTP server. On a loopback server with the same recent-file date, aioftp 0.10.1 and the immediate fix parent printed 19000927232500. The correcting commit and 0.11.0 printed 20170927232500. The filesystem timestamp was September 27, 2017 at 23:25 UTC. The older file and machine-readable directory listing gave the right year in all four builds.
What CoroPerf showed
The legacy listing sent “Sep 27 23:25”. A separate FTP client read the same bytes. At parse_ls_date the old client held a struct_time whose year was 1900. The corrected parser held a datetime with year 2017. CPython caught the library creating its internal _to_list coroutine and matched the retained object to the frame returning the rows to the reporter.
Scope and limits
The reporter’s get_info function ran unchanged with a local endpoint and Linux event loop. The server used a small synthetic ZIP under the reported filename. Its read-only directory and both client processes used October 10, 2017 UTC as their wall clock. Coverage comprises these two files, two listings and four builds. The upstream test file accompanying the patch is included as source.
