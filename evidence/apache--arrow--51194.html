Issue findings

Local observation
The reporter passed −2.5 and 2.5 to PyArrow and to a pandas Series backed by Arrow. The first prefix contains only −2.5. Both calls on 25.0.1 returned 2.2250738585072014e-308 for that prefix. Both calls on 26.0.0 returned −2.5. In a separate five-row IPC job the affected release produced four wrong prefixes. Supplying the first observation as the explicit start restored both values on the original fixture.
What CoroPerf showed
GDB stopped before and after the float64 maximum instruction in the shipped compute library. The accumulator on 25.0.1 started at the smallest positive normal double and retained it when compared with −2.5. On 26.0.0 the accumulator started at negative infinity and took the observed value −2.5. The direct and chunked paths reached the same Max accumulator through Arrow’s vector executor. The landed change replaced the floating-point default maximum seed with negative infinity.
Scope and limits
The physical samples come from the synchronous reporter program. The Fairbanks job ran separately on NOAA’s 366 daily highs for 2024. Its three float64 paths gave the same wrong year-to-date high for 43 dates, through February 12. The correct high on January 1 was −19.3 °C. On February 13 the daily high reached +5.0 °C and all paths agreed. Integer tenths matched every date on both releases. A fresh extracted replay reproduced every weather IPC file and result JSON byte for byte against both independently supplied batches.
