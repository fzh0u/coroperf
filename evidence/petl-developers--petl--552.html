Issue findings

Local observation
The reporter passed six rows to petl.aggregate with key=['foo'] and aggregation=len. The first group key was the string 'aaa'. petl 1.7.4 printed it as three cells, followed by the correct count 2. The table header still named only two columns, foo and value. Iterating the returned table exposed the same four fields seen in the printout. The other groups split 'bbb' and 'ccc' in the same way. In 1.7.6 each row held a complete key and its count. A SQLite GROUP BY on the original six rows independently returned ('aaa', 2), ('bbb', 3) and ('ccc', 1).
What CoroPerf showed
While print(table2) rendered the reporter’s table, CPython recorded the actual generator yield in petl.transform.reductions.itersimpleaggregate. Segment 1 holds the two-column header. In segment 2, the local group value k is 'aaa' and the key selector is ['foo']. On 1.7.4, line 277 yields tuple(k) + (aggregation(grp),), expanding the string into three characters. The landed code unwraps a one-element list or tuple before deciding how to emit the group. On 1.7.6, segment 2 at line 290 returns ('aaa', 2). Changing only the selector to the scalar 'foo' gave the expected result on all five builds. A one-element tuple reproduced the list behavior. A second input used unequal-length product names and summed quantities. The affected rows for apple, apricot and pear had six, eight and five fields under a two-field header. The numeric sums matched SQLite across builds. Grouping by both product and region also matched SQLite on every build.
Scope and limits
The reported release was petl 1.7.4 on Python 3.8.5. This replay used CPython 3.10.12 and the full posted code block, including its print statement. It exercised the simple aggregate implementation. The two source packages were built with upstream setup.py. The earlier 1.7.5 tag and its PyPI distribution still have the affected implementation. PyPI uploaded that distribution on February 5, 2022, three days after uploading 1.7.6. The stack observations follow synchronous generator yields. The coroutine-origin count is zero.
