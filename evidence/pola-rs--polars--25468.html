Issue findings

Local observation
With allow_exact_matches=False, every row of the five-date example matched itself on Polars 1.22.0. On 1.36.1 the matched row IDs were [2, 3, 4, 5, 4]. The older nearest join also paired each of 12 USGS earthquakes with itself. Both an exhaustive Python search and a SQLite ranking query agreed on the nearest distinct event for every row.
What CoroPerf showed
Inside the Rust nearest-neighbor kernel, the old scan evaluated an equal right-hand key while its allow-equality flag was false. Its distance of zero beat the preceding date. The fixed iterator skipped that key and compared the strictly earlier and later dates. At a midpoint in the reported five-date input it selected the later date.
Scope and limits
Five builds ran the posted program and 54 control joins each. The controls include duplicate keys, empty tables, missing neighbors and both directional strategies. GDB captured operand values from the parent and fix source builds. The 1.22.0 release wheel supplied a function stack. The joins ran synchronously.
