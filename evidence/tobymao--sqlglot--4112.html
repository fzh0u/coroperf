Issue findings

Local observation
The reporter’s query raised “Cannot automatically join: c_id” three times each on 25.21.1 and the fix parent. The original SQL returned seven PostgreSQL rows, and both fixed builds emitted the exact expected SQL.
What CoroPerf showed
After skipping the first ON clause, _expand_using knew only a.b_id and could not resolve b.c_id. Registering b first yielded the correct join condition and the same rows as PostgreSQL.
Scope and limits
The report did not pin a version. Adjacent releases and commits were checked against locally constructed data in a synchronous optimizer.
