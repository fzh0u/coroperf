Issue findings

Local observation
The reported revision and checked main run two probes that both return HTTP 503. Each run also completes one workload request and records one workload failure. The console and saved JSON omit both probe counters. Open PR #69262 and the same patch applied to main report 0 completed probes and 2 failed probes. Probe latency fields remain absent when every probe fails. The mixed, success-only, and disabled-probe controls preserve the expected reports.
What CoroPerf showed
All three failed responses reach the same aiohttp receive stack outside an active Task. The live ResponseHandler links each callback to its send. The sending asyncio Task links observations 1 and 2 to one probe creation at record 0, and observation 4 to the workload creation at record 3. The returned RequestFuncOutput objects are the same objects in the benchmark's two result lists, so the missing counters can be attributed to the two verified probe failures.
Scope and limits
The original benchmark parser, scheduler, HTTP client, console summary and JSON writer run against fixed responses on a loopback endpoint. This verifies reporting and ownership in the benchmark client. Model inference and serving throughput are unmeasured. The issue and PR remain open.
