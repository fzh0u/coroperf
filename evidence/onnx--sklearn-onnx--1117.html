Issue findings

Local observation
The released converter reproduced the report’s 28 out-of-tolerance values among 2,000 probabilities. Fourteen input rows were affected, including two whose predicted labels changed. In the held-out digits 0 and 1 test, 202 of 360 images had a probability discrepancy and all labels agreed. The other two digit pairs and the ten-class run met the original tolerance.
What CoroPerf showed
Every input took the same tree branches as in scikit-learn. For binary leaves the converter kept only the second class weight. In trees 25 and 34 the retained values rounded to exactly 1 in float32, and the runtime returned 0 for the first class. The original probabilities were about 1.63e-8 and 9.79e-9. Clipping replaced zero with 2.22e-16 before the boost graph took its logarithm. The converter stacks expose the values before and after serialization. Replacing just these two trees’ weight attributes in the exported model removed all 28 discrepancies.
Scope and limits
The report specified Python, scikit-learn and converter versions. The local CPU runtime was ONNX Runtime 1.18.1, available before the report. The two-weight encoding is a local control. The converter ran synchronously. The captured Python stacks establish the export path, and the ONNX Runtime profile records the later CPU kernels. Tree indices start at zero.
