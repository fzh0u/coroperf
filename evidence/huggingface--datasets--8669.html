Issue findings

Local observation
Across 19 Parquet files, Datasets 5.0.1 delivered 152/0/0/0 rows to four workers, versus 40/40/40/32 on 5.1.0, with all 152 unique rows delivered in both cases.
What CoroPerf showed
Disabling shuffle or limiting the input buffer to one shard restored a 5/5/5/4 file split, and the fix constructs each worker’s interleaved reader after assigning its source shards.
Scope and limits
The data run used small local files and one CPU node. Only CelebA metadata was tested, with no multi-rank or sustained resource measurements.
