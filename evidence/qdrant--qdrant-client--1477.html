Issue findings

Local observation
The reporter’s first program wrote the same UUID in uppercase, compact and canonical form. Client 1.19.1 counted three points and still had two after deletion. Client 1.20.0 counted one and deleted it. A second original program passed the previous page’s cursor back as a UUID object. The affected client raised TypeError. The fixed client returned the next two points.
What CoroPerf showed
All three writes reached _add_point on the same local collection, with a different string key each time. The fix canonicalized the UUID, so the second and third writes reached _update_point. The cursor sample shows the comparison receiving the same identifier the previous page returned. With the fix, normalization runs before the comparison. Independent vector queries and SQLite reads show which revisions survived.
Scope and limits
The original calls are synchronous. A separate upstream async regression failed on the affected builds and passed on both fixed builds. The Rust 1.17.1 server supplied an independent reference through its HTTP API. The issue author describes an agent-assisted discovery followed by a personal rerun.
