Issue findings

Local observation
Two RPCs call the same method with the same payload. On the reported gRPC build, the request ID is present when each asyncio server Task submits its work, and both sync handlers read None on the worker threads. The proposed context-copy change restores the ID. On both builds, the inspected worker stacks and Task diagnostics omit both interceptor routes.
What CoroPerf showed
The active WorkItem connects the worker's read_request_id stack to its creation under run_in_executor. At submission, that WorkItem holds the exact handler created earlier by the same server Task inside route_profile or route_inventory. Both boundaries are recorded. Removing the handler-to-WorkItem edge keeps the worker-to-submission join and loses the earlier route.
Scope and limits
The original report was reproduced separately. The stacks below use a controlled two-request replay on the reported gRPC Cython build and CPython 3.9.18, with a selected Task and WorkItem probe. The context-copy comparison uses the unmerged proposal.
