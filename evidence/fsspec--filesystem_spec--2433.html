Issue findings

Local observation
The original BytesIO example failed twice after reading all four bytes, while with proposed change #2435, the stream stayed open and the caller could read back “data”.
What CoroPerf showed
Task and object identities linked the successful read to split_protocol calling startswith on the destination, while both HTTP range responses in the control contained the correct bytes.
Scope and limits
The report used one task with inline data. Concurrent callers and the loopback HTTP server were local controls.
