Issue findings

Local observation
DuckDB rejected the reporter’s five-row query because it looked for a scalar lag function. The fix commit and release returned the expected grouped values 0, 0, 2, 3, 1 in value order.
What CoroPerf showed
The old traversal skipped a NodeList containing Lag and emitted SQL without OVER. Exposing Lag directly to the traversal produced a partitioned, ordered window and the correct results.
Scope and limits
The exact Ibis revision was unspecified. The fix parent reproduced the database error in a synchronous query.
