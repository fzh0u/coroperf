Issue findings

Local observation
The posted Ibis query filled two columns. Version 1.0.0 compiled only the second replacement into its Impala SQL. On 891 Titanic passenger records, SQLite returned 688 missing decks when deck was filled first, or two missing towns when embarkation town was filled first. Version 1.1.0 filled every missing value in both orders.
What CoroPerf showed
The stack follows the second mutate call to projection, get_result and try_fusion. At entry, the prior projection contains an IfNull expression for column b. The parent commit returns a fused projection that reads b from the base table, discarding that expression. The fix declines fusion and the inner query fills b. Filling both columns in a single mutation also gives the correct value for every passenger on all four builds.
Scope and limits
The original report demonstrates Impala SQL compilation and gives no exact revision. The passenger queries ran on local SQLite. A targeted CPython probe captured the optimizer’s input and return value alongside its stack. This is a synchronous query.
