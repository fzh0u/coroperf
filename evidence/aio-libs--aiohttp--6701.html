Issue findings

Local observation
The original client read 14 bytes from the reporter’s public example using ab as a delimiter. aiohttp 3.8.1 and the fix parent ended records at bytes 3, 8, 13 and 14. The fix returned records ending at bytes 4, 9 and 14. In a CSV transfer with 244 restaurant checks, Python’s CSV reader consumed the header and then rejected the next record on both affected builds. The fix delivered all 244 data rows.
What CoroPerf showed
StreamReader.readuntil found the delimiter, but consumed only its first byte. The trace paired the first partial record with the original main Task created by run_until_complete at line 17 of the reporter’s script. The nested reads and their return sizes explain the observed split. The fix consumed the full delimiter. Concatenating the returned pieces recovered the original body on every build.
Scope and limits
The report used macOS and Python 3.8.9. The local runs used Linux and Python 3.10.12. The reporter’s original client, a URL-only loopback replay and eight stream controls ran with and without instrumentation. The restaurant data was served with CRLF endings using Content-Length and chunked transfer. Both deliveries kept each delimiter together in the server’s writes. The coroutine origin belongs to the original client.
