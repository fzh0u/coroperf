Issue findings

Local observation
Two faulted chains interleave on one worker. Stock EventPipe records 16 exceptions with identical type and message, including 14 rethrows with identical stacks. The final Exception.StackTrace shows propagation through Chain. The EventPipe exception records and final stacks omit both synchronous launchers. Successful chains produce zero exceptions. Forwarding directly to the same leaves produces only the two initial throws.
What CoroPerf showed
FirstChanceException provides the exact Exception object for each first throw and rethrow. The completed root Task holds that same object as its fault, so CoroPerf can join every throw stack back to the initial Task record. In the displayed run, LaunchInventory contributes two rethrows (representative edge 1 → 4) and LaunchProfile contributes twelve (0 → 5). Reversing the launch or release order leaves object matching intact. Swapping the depths moves the rethrow count to the other caller.
Scope and limits
This controlled Linux x86-64 replay uses CoreCLR 8.0.34 and 10.0.0 with a single continuation queue. It quantifies throws and rethrows. The probe saves in-process first-chance events and inspects root Task faults after completion. The example uses faulted Tasks. Across two fresh batches, 512 matched throw observations include 448 rethrows. Withholding the identity matched through root Task faults leaves every throw unassigned.
