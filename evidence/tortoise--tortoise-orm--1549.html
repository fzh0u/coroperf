Issue findings

Local observation
A view created a record with a two-place DecimalField and serialized it with the Pydantic model generated by Tortoise. On 0.20.0 and 1.1.8, six of eight amounts lost their declared scale in the creation response on both databases. A later GET returned 2E+2 from SQLite and 200.00 from PostgreSQL for the same posted amount.
What CoroPerf showed
The request stack reached Model.create and DecimalField.to_python_value. In that frame the native normalize method received an already quantized 200.00, and the field returned 2E+2. Pydantic emitted that value in the response. PostgreSQL stored 200.00 in a numeric(12,2) column and later returned a native Decimal. SQLite stored text and ran field conversion on each read. The two upstream regression tests failed at their scale assertions on the parent commit and passed on the merge.
Scope and limits
The reporter supplied steps and a screenshot. We rebuilt the HTTP view with the specified ORM and serializer. Two batches each made 368 loopback requests using 26 service processes. Numeric equality held for every amount. The origin match identifies the measured ASGI endpoint coroutine. The Decimal operand came from a targeted CPython callback while its field frame was running.
