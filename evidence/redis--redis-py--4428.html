Issue findings

Local observation
The reporter’s four synchronous sorted-set calls reproduced on a local Redis server. With decoding enabled, the default protocol returned scores as bytes. Explicit RESP2 returned text. An asyncio rank query for the east board then returned a score of b'2.5' on the reported revision and '2.5' on the fix. The 8.2.0b1 prerelease also returned text.
What CoroPerf showed
The rank callback received the same list [1, 2.5] in both builds. The affected converter produced bytes even with decoding enabled. In the two-board run, the creation stack in read_directory and the sample inside _score_to_resp2_bytes identify the same east-board task. Redis CLI and a separate protocol reader confirmed the stored scores and ranks.
Scope and limits
The original reproducer is synchronous. Its connection endpoint was redirected to a private local Redis 8.10.2 Unix socket. The coroutine origin belongs to a separate two-board asyncio query that reproduced the same conversion error. The tested published client package is a prerelease.
