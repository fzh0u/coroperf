Issue findings

Local observation
With ABC and DEF padded to three tokens, both builds emitted IDs [50257, 24694, 32988]. The old build assigned sequence IDs [0, 1, None], so selecting the second sequence returned ABC. The fixed build assigned [None, 0, 1] and returned DEF.
What CoroPerf showed
The native Encoding kept its original sequence ranges after left padding. The fix moved both ends of each range by the padding length, and the upstream Rust regression passed. Right padding and unpadded inputs were correct.
Scope and limits
The report did not specify a release. Official builds and the Encoding component bracket the fix. GDB sampled synchronous Rust calls.
