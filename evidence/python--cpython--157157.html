Issue findings

Local observation
With a short event-loop stall, TaskGroup propagates CancelledError with empty arguments after accepting an external cancel('outside'). In the event-gated control, the error retains 'outside'. The native traceback, Task stack, creation trace, coroutine origin, and live asyncio call graph omit both cancellation request stacks.
What CoroPerf showed
The internal cancellation at record 2 sets the pending flag. The same completion Future is cancelled when the external request arrives, and its message-less CancelledError appears at record 5. The external request at record 4 raises the target Task's cancellation count to two and stores 'outside' on the Task. At record 8, TaskGroup raises the same exception object seen at 5, with empty arguments. Joining 4 to 8 exposes the accepted request whose message is absent. With event synchronization the external request instead cancels a different, pending Future, and that Future's exception is propagated with 'outside'.
Scope and limits
The local replay uses CPython 3.15.2 and the standard C Task implementation. It compares two external callers and two timing conditions, with 48 request-to-observation joins across two batches. The probe observes real Task.cancel calls and TaskGroup exit events. Upstream PR #157158 makes the test deterministic by changing its timing. The stalled-loop case remains observable on this runtime.
