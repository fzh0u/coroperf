Issue findings

Local observation
The reporter fed DBSTREAM one observation at each of (0, 0), (50, 50) and (100, 100), then printed the centers and weights in its clusters property. River kept three micro-clusters, each of weight 1. With minimum_weight set to 5, zero qualified for the result. River 0.23.0 printed all three. The exact parent reproduced those three lines. The merged source, 0.24.1 and 0.24.2 printed no lines and returned an empty mapping. With isolated weights [5, 4, 6], the fix returned the first and third centers. With weights [5, 5], every build returned both.
What CoroPerf showed
In the 0.23.0 trace the reported property called _recluster, then _generate_labels. The weighted adjacency map was empty. The labeler assigned 0, 1 and 2 to the three weight-one micro-clusters (segments 10, 12, 14). The label map returned in segment 15 was the same object passed to assembly. The public property returned its three-entry result. In 0.24.2 the weight check skipped all three (segments 11, 14, 17). The three labels remained None and assembly returned an empty dictionary. Both traces reached these decisions before periodic cleanup. The landed change checks each micro-cluster’s weight before assigning a label and handles the empty set of assigned labels. A separate stream formed two neighboring micro-clusters of weight 14. Both contributed to a single weight-28 center at x ≈ 0.75 through an edge of density 4/7. After one observation at x = 50, predict_one selected the new singleton on 0.23.0 and the parent. The fixed builds still selected the weight-28 center. Four more observations brought the distant point to weight 5, and each of the four builds in this control selected it.
Scope and limits
The exact source builds both reported version 0.23.0. Their commits and loaded DBSTREAM file hashes identify immediate parent 7b1da16c8b and landed fix f72a0da16a. The 0.24.0 release tag contains the corrected module. Its yanked Linux CPython 3.12 wheel omitted it, so the reporter’s import failed. The 0.24.1 wheel ran the corrected code. PyPI yanked that release for missing source-distribution files. Version 0.24.2 was the first non-yanked successor tested. Cluster counts come from the public mapping. With no output centers, predict_one can still return its default label 0. The physical samples cover synchronous CPython calls and contribute zero coroutine origins.
