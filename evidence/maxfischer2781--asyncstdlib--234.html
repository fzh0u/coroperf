Issue findings

Local observation
For tied keys, descending merge yielded the second source first, while heapq.merge yielded the first, and correcting the order also changed which SQLite partition supplied both top results.
What CoroPerf showed
Equal keys carried source indices 0 and −1, so the second source left the heap first, and changing only the key comparator preserved the error, while correcting the source indices resolved it.
Scope and limits
The original example and upstream regression test ran locally. The three-partition SQLite selection was a separate control.
