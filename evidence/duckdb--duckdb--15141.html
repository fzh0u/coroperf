Issue findings

Local observation
The reporter’s four-row query came back out of order in 47 of 64 eight-thread runs on 1.1.3 and in none of 64 runs in either round on 1.2.0. Timestamps and grouped sums agreed.
What CoroPerf showed
The old syntax tree lacked the modifiers and the plan lacked sorting or pagination. Adding the upstream TransformModifiers call and rebuilding that file restored both ordering and pagination.
Scope and limits
Linux releases and source builds replaced the reporter’s Windows build. Hash-group output order varied between runs.
