Issue findings

Local observation
Three voters and one configured non-voter joined a local cluster. With DNS-SRV discovery, all four status responses on 8.14.0 listed the fourth member as Voter. Version 8.14.1 listed it as Nonvoter. All four nodes read back the same SQL row in both versions.
What CoroPerf showed
The DNS-SRV join path in 8.14.0 supplied a constant Voter flag. The leader received true and recorded AddVoter. The fixed code forwarded the configuration flag and recorded AddNonvoter. Runtime events matched the leader’s join handler to the exact goroutine created by the cluster service for the connection.
Scope and limits
The local cluster used four real processes and DNS SRV/A queries on loopback. It did not recreate the reporter’s Kubernetes, TLS or authentication setup. The matched goroutine is the leader-side connection handler; the replica’s sending stack was observed in a separate process.
