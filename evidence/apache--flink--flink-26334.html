Issue findings

Local observation
The reporter’s eight events produced seven five-second windows in Flink 1.14.3. Three timestamps landed one window late. The events at −7,000 and −2,000 ms both printed a group size of two. Flink 1.14.5 produced eight singleton windows. Shifting the original stream forward by 20 seconds gave eight correct windows on both releases.
What CoroPerf showed
WindowOperator.processElement passed record c to TumblingEventTimeWindows.assignWindows. The helper received −7,000 ms, offset zero and width 5,000 ms. The affected signed-remainder expression returned −5,000. JDI then read the actual returned window [−5,000, 0). In the fixed JVM the helper had a remainder of −2,000 and returned −10,000. The assigner returned [−10,000, −5,000). Both starts matched the print sink. The physical frames, return values and shipped bytecode tie the discrepancy to the window-start calculation.
Scope and limits
The original program used eight synthetic timestamps and five-second windows. A separate job used 76 USGS earthquakes and seven-day windows aligned to the Unix epoch. Both jobs also ran without a debugger. The catalog output matched two earlier batches byte for byte on each release. The six captures measure physical JVM task-thread frames. Coroutine creation was unobserved.
