Issue findings

Local observation
Two one-shot watches on /message delivered the committed values goodbye world and sup, world. After each delivery, the official 2.0.0 and 2.0.8 releases reported 18446744073709551615 and 18446744073709551614 active watchers. Version 2.0.9 returned zero both times. Two fresh batches reproduced the sequence.
What CoroPerf showed
Go recorded the creation of the apply goroutine at EtcdServer.start. That same GoID reached notifyWatchers while applying the committed PUT. The parent decremented the signed count and left the watcher’s removed flag false. The watch connection then cleaned up the same watcher and decremented the count again. The stats endpoint serialized −1 and −2 as unsigned integers. The fix sets the flag in the notification path. HTTP cleanup then leaves the count alone.
Scope and limits
The reported 2.0.0 binary and the adjacent release binaries ran unmodified on Linux/amd64. Physical stacks came from the release-branch parent and fix built with Go 1.23.0. The three-voter source runs opened the watches on n0 and submitted the writes on n1. Each member reported its own count and all three members read back each committed change.
