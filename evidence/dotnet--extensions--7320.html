Issue findings

Local observation
In Microsoft.Extensions.AI 10.3.0, two streaming requests each produce a tool span and a follow-up chat span with a new TraceId and an empty parent SpanId. Both initial chat spans are connected to their original agent. The same scenario keeps all spans attached in 10.2.0 and 10.4.0. All three versions complete one tool call, two model calls and the same streamed result per request. The results hold on .NET 8 and .NET 10 and in both launch orders.
What CoroPerf showed
Both disconnected follow-ups have identical physical stacks through OpenTelemetryChatClient and FunctionInvokingChatClient. At each observation, the actual original ChatMessage remains in the follow-up input while its recorded IAsyncEnumerator has an outstanding MoveNextAsync. Matching those object identities connects batch execution record 2 to creation record 1 and interactive execution record 3 to creation record 0. The later launch reaches its follow-up first. Reversing both orders preserves the matches. The original agent TraceIds and caller frames are available after the joins even when the exported follow-up spans form new roots.
Scope and limits
The replay runs released Microsoft.Extensions.AI assemblies on .NET 8.0.34 and 10.0.0, with the real OpenTelemetryChatClient and FunctionInvokingChatClient, a local tool, and a scripted model provider as in the upstream regression test. A standard ActivityListener independently records completed spans. The evidence page shows the .NET 8 replay on the affected 10.3.0 package. The issue is closed. Merged PR #7321 guards the Activity.Current assignments after yields, and the 10.4.0 package passes the replay.
