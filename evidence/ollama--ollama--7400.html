Issue findings

Local observation
With all-minilm already loaded in the CPU runner, the first 12-text request takes a median 134.3 ms after runner acquisition on the historical base and 100.1 ms with the local adaptation of PR #7424. Warm medians are 101.0 and 96.8 ms. The first vocabulary load costs 26.8–27.5 ms in the two traced orders. All embedding coordinates match exactly. The proposal counts two extra special tokens per text.
What CoroPerf showed
The catalog and query workers have identical Embedding stacks. The exact Go context ticket carries the initiating HTTP request and input row into the errgroup worker. Its payload fingerprint agrees with the preflight tokenization and the separate runner's JSON input. Execution record 1 joins to the catalog worker's creation 0. Execution record 3 joins to the query worker's creation 2. The first request's host vocabulary load and per-row tokenizations finish before it creates its workers. Reversing the requests moves the vocabulary cost from the twelve-row catalog batch to the one-row query.
Scope and limits
The replay uses real loopback /api/embed and the historical CPU runner with ordinary in-context text. An empty request primes the runner before each comparison. Each cold median uses five fresh processes per arm and task order. The warm medians pool 35 requests per shape and arm. The proposal adaptation removes the shared counter update by storing counts per row. This isolates historical endpoint overhead. The candidate changes reported token counts and the original Sentence Transformers comparison is outside the experiment. Issue #7400 is open and PR #7424 closed without merging.
