Issue findings

Local observation
The reporter saved a list containing Decimal('0.1') and awaited the first row. On SQLite, Piccolo 1.38.0 returned a Python float. Its display is 0.1 and its exact binary value is slightly above one tenth. The scalar Numeric column returned Decimal('0.1') in the same environment. PostgreSQL returned Decimal('0.10') from its numeric array on every build. With a table created and read by Piccolo 1.39.0, SQLite returned Decimal('0.1'). The first table shows one element of each returned row. The type affects ordinary arithmetic. A second SQLite row held the two input prices 0.10 and 0.20. The JSON bytes on disk were [0.1, 0.2] in both schemas. Adding the two returned floats yielded 0.30000000000000004. Adding the two returned Decimals yielded Decimal('0.3'), equal to thirty cents.
What CoroPerf showed
The earlier code declared the SQLite column as ARRAY. Fetching the row invoked convert_array_out, whose JSON decoder produced a list of floats. The landed change gives a new numeric-array column the declaration ARRAY_NUMERIC(5, 2). Its converter also handles numeric JSON elements, passing their string forms to decimal conversion. In the crossed reads, each reader opened exactly the same saved database as the other reader. The fixed reader still returned floats from the old ARRAY column. The old reader also returned floats from the new declaration. The new declaration and the new reader together produced Decimal values. The prior equality check could pass on 50.0 because the float equals Decimal('50.0'). The landed test checks the element’s Python type. The reported await at posted.py line 5 entered Proxy.__await__, which created First.run at piccolo/query/proxy.py line 40. In the 1.38.0 SQLite graph, segment 1 records that unstarted coroutine. Segment 21 samples the same object and frame at select.py line 102 as it returns the selected row. A separate aiosqlite worker executed fetchall and returned the converted list at segment 14. The fetch job’s Future, the bound cursor and the returned element’s identity connect that worker to the row delivered on the event-loop thread. On 1.39.0 the corresponding worker returned a list containing a Decimal at segment 16.
Scope and limits
The issue supplies an awaited code block and identifies SQLite and PostgreSQL. It gives no exact library, driver or server versions. The 1.38.0 wheel was current at opening, and 1.39.0 shipped after PR #1445. The replay supplies imports, starts each database and creates the table before running the posted block. It tests CPython 3.11.15, SQLite 3.53.1 and PostgreSQL 10.23. Installing the corrected reader leaves pre-existing SQLite column declarations in place. The tested SQLite JSON representation also drops trailing zeroes in the paired prices. PostgreSQL retained the two-place decimal scale. A separate PostgreSQL numeric_send read confirmed the value and scale. The coroutine-origin count for this issue is one, for the select coroutine. The worker conversions and Future callbacks have their own physical stack records.
