Issue findings

Local observation
The broker persisted the posted Go CLI request with Test: ø, but both Core and JetStream pull consumers on 2.14.0 received the body with empty headers, losing the ASCII Batch field too.
What CoroPerf showed
The read task failed during client decoding. Object identities linked that message to the error callback and pull result, and the fixed decoders matched PR #928.
Scope and limits
The replay used the default parser and NATS 2.10.26. Task attribution covers the pull connection’s reader. Production messages and dead-letter handling were unavailable.
