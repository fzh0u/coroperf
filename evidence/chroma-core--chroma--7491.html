Issue findings

Local observation
Chroma 1.5.9 returned both int2 and float2_5 for equality with 2.5. It also omitted int2 when asked for values below 2.5. On 178 Wine measurements with mixed numeric types, 30 of 56 filters returned incorrect ID sets. Across those filters, 288 record memberships differed from direct numeric comparisons.
What CoroPerf showed
The native Rust stack reached the helper that builds one SQL branch per storage type. On the parent build, the integer threshold read 2 and the floating-point threshold read 2.5. The SQLite worker bound those values and executed the union. In the proposed build the integer equality branch evaluated to false. For the greater-than-or-equal filter its threshold was 3. Replaying the same statements and bindings against the saved databases returned the same IDs.
Scope and limits
The reported wheel and two Rust source builds ran on Linux x86_64. The reporter used macOS ARM64. Membership comparisons ignore the order of IDs. The Wine workload uses ordinary finite measurements. The comparison build is the head of an open proposal. Each native capture identifies the executing thread.
