Issue findings

Local observation
With async-lru 2.0.2, all 20 cache computations finish. Fifteen completion callbacks raise KeyError and leave fifteen requests waiting. The stock asyncio debug traceback identifies the callback and the missing key. The surviving Task stacks, Task creation tracebacks, and coroutine origins omit both original launchers. On 2.0.3 the same evictions occur and all twenty results are delivered.
What CoroPerf showed
In the displayed replay, the request for key 5 evicts key 0. The eviction (record 52), failing callback (97), and still-waiting Task (141) all hold the same cache result Future. CoroPerf separately joins 52 to the creation of key 5's Task (26), then its dispatch Handle at launch_inventory (6). It joins 141 to the creation of key 0's Task (21), then its dispatch Handle at launch_profile (1). The event-loop callback is a separate observation.
Scope and limits
This is a controlled two-caller extension of the upstream example on CPython 3.11.18. Two batches verify 480 caller joins across 240 eviction pairs on async-lru 2.0.2 and 2.0.3, with independently reversed submission and swapped callers. The scoped probes read Task, Handle, and Future identities from the running program. Withholding the Handle edges leaves both callers absent. The harness records pending requests after the workers and callbacks have run, then cancels them to exit.
