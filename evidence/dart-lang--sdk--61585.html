Issue findings

Local observation
Two unawaited calls run the same Future.forEach interceptor chain. At CInterceptor.onRequest, both StackTrace.current and the VM Service stack views show identical locations for the two invocations on each tested SDK. On 3.5.3 the async chain ends within the Future loop. On 3.14.0 it reaches testFuture. Both feature launchers are absent on each version.
What CoroPerf showed
At binding, the probe records the actual nextIteration closure and its live stack. When the interceptor runs, it uses Dart identical to compare the active Future listener's callback with both previously observed closures. That exact object selects the creation stack. In the displayed run, featureB reaches the interceptor first and matches records 1 → 2. The second interceptor matches featureA at 0 → 3. Withholding the callback match leaves both stacks unassigned.
Scope and limits
This Linux x86-64 JIT replay uses Dart SDK 3.5.3 and 3.14.0. It uses VM Service breakpoints and does not replace SDK callbacks. An independent check uses separate interceptor instance records. Two batches verify 32 joins with launch order and first-interceptor release order varied independently.
