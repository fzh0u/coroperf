Issue findings

Local observation
Opening a real JSON file against the v0.10.3 example server produced a diagnostic notification but an empty server traceback for the injected exception in did_open.
What CoroPerf showed
The completion callback had no current exception, though the Future held did_open’s ZeroDivisionError. Version 0.11.0 logged the handler on the same input, and the original example worked without the injected error. The Task created by _execute_notification threw in did_open. The completion callback received that Task and its coroutine object.
Scope and limits
A local LSP client drove the extension server. The VS Code interface was untested.
