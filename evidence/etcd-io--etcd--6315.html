Issue findings

Local observation
The released 3.0.6 client wrote 14 bytes for the 12-byte value created-key1. Repeating the posted transaction took the success branch and added the same two quote bytes to overwrote-key1. In a 249-entry country catalog, all 80 names submitted in quotes acquired the extra characters. All 169 unquoted names were correct. Reads on three distinct members agreed before and after a cluster restart in both batches.
What CoroPerf showed
The physical Go stack reaches argify through parseRequestUnion and readOps. On the released parser, argify returned the quoted text as a token. The put handler then passed the same bytes into the client operation. Changing only argify to the upstream implementation removed the extra characters at both observation points and in persistent storage. The released 3.1.0 client independently produced the same correct values.
Scope and limits
The report omitted the client version. The reproduction used a 3.0.6 client available before the report and a local three-member 3.5.33 cluster. Stack capture used two 3.0.6 source builds with Go 1.9.2. The observed parser calls ran synchronously. The evidence establishes the value conversion in the client.
