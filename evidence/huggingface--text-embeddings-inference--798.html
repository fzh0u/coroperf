Issue findings

Local observation
While the backend holds its first dequeued batch, capacity one already allows one more batch to be prepared. The local capacity-four option allows four. Both launch orders return the same seven embeddings per pipeline. In the real CPU router, capacity four has a small throughput gain for single-request batches and a small loss when batching up to four requests. The returned vectors match the default and upstream router in both comparisons.
What CoroPerf showed
Both batching tasks return Pending while reserving a slot and have identical native stacks on the same Tokio thread. The actual Task ID and sender channel join each sample to its spawn site. The original initialization Task joins that creation back to launch_catalog or launch_search. Reversing both launches swaps their ownership of the same two stacks.
Scope and limits
The traced experiment intentionally pauses the backend after its first dequeue and uses a real Candle CPU model. Timings come from separate uninstrumented loopback runs with bge-micro and two token budgets. They cover the tested CPU workload. The capacity option was tested locally and the GitHub issue is open.
