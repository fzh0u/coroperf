Issue findings

Local observation
The original handler tells clients it supports GET and OPTIONS. Tornado 6.0.3, 6.0.4 and the immediate source parent dropped Allow from the 204 response. All five builds transmitted the reporter’s custom Alloww header. Changing only the status to 200 preserved both headers on every build.
What CoroPerf showed
The affected filter received both headers. Its clear_header call took the argument Allow, deleted that entry on the live handler and returned to finish. The HTTP writer then received only the custom header of the two. The landed filter preserves Allow, and curl received it on both the merged revision and Tornado 6.1. The archived source change removes Allow from the list of headers the filter clears.
Scope and limits
The two trials used the reporter’s entire server and curl command on loopback with CPython 3.9.15. The reporter gave the Tornado version only. The coroutine witness belongs to the framework’s RequestHandler._execute. The application method options and the header filter both ran synchronously inside it. The comparison covers the posted 204 response, the 200 status control and a GET.
