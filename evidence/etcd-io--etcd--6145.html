Issue findings

Local observation
The posted etcdctl range query requested two keys from key1 up to the exclusive bound key5. Each of three servers returned key1 and key2. The affected response reported three matches although four keys matched. The fixed response reported four. Across the four clusters, 12 of 26 affected reads and none of 26 fixed reads reported a wrong total.
What CoroPerf showed
The trace links the FIFO scheduler’s creation of the Raft apply worker to rangeKeys handling this committed request. The index found four matches. To decide whether another page existed, the range read fetched three values. The affected result used that fetch length for its total. The fixed result used the index count while still fetching only three values. The retained WALs identify the requests and revisions on all three replicas.
Scope and limits
The report did not specify a revision or cluster topology. The local clusters used the first parent and the merged fix. Native goroutine traces cover the first node of each observed cluster. Stock runs independently verified the visible command output.
