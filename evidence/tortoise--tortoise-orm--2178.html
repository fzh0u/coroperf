Issue findings

Local observation
The reporter’s query returned users 101 and 102 on Tortoise ORM 0.25.3, but reported a total of three. One user matched both selected roles. The fix and release 1.1.9 returned the same two users and a total of two.
What CoroPerf showed
QuerySet.count received a distinct queryset. In the affected build the new CountQuery lacked its distinct flag, and PostgreSQL executed COUNT(*) over the joined role rows. The fix passed the flag through and counted distinct user IDs. Replaying the logged statements with one role membership removed, restored and then added to the second user moved the old count from 3 to 2 to 3 to 4. The fixed count stayed at 2.
Scope and limits
The report supplied the query body, Python version, ORM version and driver. The local run supplied the missing models and records. The creation stack belongs to a request in our asyncio Unix-socket service. The same query was also run directly on PostgreSQL. The upstream regression used SQLite.
