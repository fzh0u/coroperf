Issue findings

Local observation
Transformed keys reached the wrapped function and appeared in its results, and a repeated request for the same two Redis keys ran the function again.
What CoroPerf showed
The write task passed doubly prefixed keys to _multi_set while the reader looked up singly prefixed keys; aligning the two made overlapping requests fetch only new items.
Scope and limits
The report used an in-memory cache and gave no version. Redis was a separate control for 0.12.3 and a development-branch change.
