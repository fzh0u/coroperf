Issue findings

Local observation
Two caller threads launch the same effect, and both worker fibers fail with the same message. On Scalaz ZIO 1.0-RC5, the native trace and failure report differ only in Fiber ID. An all-thread Java stack snapshot shows both blocked unsafeRun calls but no link to a particular worker fiber. On the upstream fix, each native fiber trace includes its own unsafeRun source line.
What CoroPerf showed
CoroPerf matches the actual FiberContext receiver observed by JDI at construction to the receiver of captureTrace on the worker failure path. The two joins recover importOrders at Gateways.scala line 42 and refreshCatalog at line 45. Each pair is checked against the separately recorded runtime Fiber ID and worker thread.
Scope and limits
The issue reports missing diagnostics. This case uses a controlled two-fiber replay on Scala 2.12.8 and JVM 8, with JDI observing the original 1.0-RC5 runtime. The Java stack snapshot is taken while both unsafeRun calls are active.
