Issue findings

Local observation
When MySQL rejected a second insert with the same primary key, the old QueryFailedError stack began at Query.onResult and omitted myNamedFunction1234.
What CoroPerf showed
The upstream regression linked the error to the named function’s returned promise, and throwing from query’s catch restored InsertQueryBuilder.execute and the second insert’s call site. The sampled stack is the rejected Promise’s saved error stack, read in Chai’s callback. The callback’s execution ID is separate from the Promise ID.
Scope and limits
The public regression used a duplicate key. Both builds returned 1062/23000 and retained the original row; promise identity was verified for the test function.
