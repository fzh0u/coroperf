Issue findings

Local observation
With prefix insertion disabled and offset trimming enabled, the first token in “ My name is John” covered characters 0–3 and included the space. Setting add_prefix_space=False on the post-processor moved the start to 1. The four token IDs stayed the same across both configurations on all five builds.
What CoroPerf showed
The native stack follows Python encode() to the Rust process_offsets branch. The default post-processor treated the first leading space as an inserted prefix and reduced the trim count from one to zero. Matching the pre-tokenizer setting kept the trim count at one. The cited revision already accepted this keyword. The closing change documented it and added tests.
Scope and limits
The report gave the configuration and a source revision. The local experiment used RoBERTa vocabulary files and examined character offsets. In 697 SQuAD answer windows beginning with one real space, the aligned configuration recovered all 697 annotated starts and 694 complete answer strings. Three annotations ended inside a token. The native samples cover synchronous encoding.
