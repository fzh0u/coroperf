Issue findings

Local observation
The reporter pooled the same two token vectors twice. On the reported commit, the fix parent and release 6.1.0, the unpadded call printed 2.3333 and the left-padded call printed 2.2000. The fixing commit and release 6.2.0 printed 2.3333 both times. In SentenceTransformer.encode, three of four STS Benchmark sentences changed when batched with a longer sentence. The largest absolute change in any embedding coordinate fell from 1.6583939 on the parent to 1.1444092e-05 on the fix. Right-padded batches matched singleton outputs exactly on all five builds.
What CoroPerf showed
A physical stack from encode reached Pooling._forward_padded. Its recorded mask and effective weights explain the two-token result. With left padding, the parent gave the real tokens weights 2 and 3, producing (2 × 1 + 3 × 3) / 5. The fix subtracted the leading padding length and gave them weights 1 and 2, producing (1 × 1 + 2 × 3) / 3. An independent sum over the actual token vectors used each token’s position within its sequence. Across all four fixed-batch embeddings, the largest coordinate difference from this calculation was 1.0146234e-06.
Scope and limits
The corpus check used four published test sentences, the SmolLM2-135M-Instruct checkpoint with its chat formatting, and an explicitly configured weighted-mean head. Token counts include the chat template. The measurements cover embedding consistency on CPU in float32. The local environment used Linux, Python 3.12.4, PyTorch 2.11.0 and Transformers 5.14.1. The pooling calls ran synchronously.
